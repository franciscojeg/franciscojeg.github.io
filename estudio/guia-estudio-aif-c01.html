Primero: qué evalúa realmente AIF-C01

Este es un examen fundacional: no te pide escribir código ni calcular métricas. Te pide entender qué puede hacer la IA, cuáles son sus riesgos y qué servicio de AWS se ajusta mejor a un caso de negocio.

  1. Identifica el dato: ¿texto, imagen, audio, documento, historial de compras o datos etiquetados?
  2. Identifica la tarea: clasificar, extraer, traducir, recomendar, pronosticar, conversar o generar contenido.
  3. Escoge el nivel de control: servicio AI listo para usar, Bedrock para IA generativa, o SageMaker para crear/entrenar ML propio.
  4. Revisa riesgos: sesgo, alucinaciones, privacidad, seguridad y supervisión humana.
Mapa mental: caso de uso → tipo de IA → servicio AWS. Ejemplo: “extraer campos de facturas escaneadas” → documento → extracción → Amazon Textract.

Dominio 1 · Fundamentos de AI y ML 20%

Conceptos desde cero
ConceptoQué significaEjemplo simple

Tipos de aprendizaje y ciclo de vida
  • Supervisado: datos con respuesta conocida. “Estas imágenes ya dicen gato/perro”; el modelo aprende a clasificar.
  • No supervisado: datos sin etiquetas; busca agrupaciones o patrones. Ejemplo: segmentar clientes por comportamiento.
  • Refuerzo: aprende por recompensas y penalizaciones. Ejemplo: un agente que mejora al jugar.
  • Ciclo ML: problema de negocio → datos → preparación → entrenamiento → evaluación → despliegue → monitoreo. Si los datos reales cambian y empeora el resultado, hay drift.
Pista: “predecir un precio usando ejemplos históricos con precio real” → aprendizaje supervisado. “agrupar clientes sin categorías previas” → no supervisado.
Métricas que debes reconocer
  • Accuracy: porcentaje total de aciertos.
  • Precision: de lo que el modelo marcó como positivo, cuántos realmente lo eran. Importa cuando un falso positivo es costoso.
  • Recall: de todos los positivos reales, cuántos encontró. Importa cuando dejar escapar un positivo es peligroso, como fraude o una enfermedad.
  • F1: equilibrio entre precision y recall.
No memorices fórmulas: identifica el costo de cada error. En fraude, suele importar más no dejar pasar fraudes reales: alto recall.

Dominio 2 · Fundamentos de IA generativa 24%

Las piezas de una aplicación generativa
  • Foundation model (FM): modelo grande preentrenado que sirve para muchas tareas.
  • LLM: FM especializado en lenguaje.
  • Token: fragmento de texto que el modelo procesa; afecta costo, límite y velocidad.
  • Ventana de contexto: cantidad máxima de tokens que el modelo considera a la vez.
  • Embedding: vector numérico que representa significado; permite buscar contenido similar aunque no use las mismas palabras.
  • Temperatura: baja = respuesta más consistente; alta = más variación/creatividad.
Pista: “buscar documentos por significado” → embeddings y búsqueda vectorial; no una búsqueda literal por palabras.
Limitaciones que nunca debes olvidar
  • Alucinación: respuesta inventada o incorrecta que parece convincente.
  • Sesgo: resultados injustos por datos, modelo o diseño.
  • No determinismo: el mismo prompt puede dar respuestas diferentes.
  • Privacidad: no debes enviar datos sensibles sin controles y autorización.
La IA generativa no es una base de datos: puede redactar con fluidez sin que su respuesta sea verdadera. Para datos empresariales actualizados, piensa en RAG y validación.

Dominio 3 · Aplicaciones de modelos fundacionales 28% · mayor peso

Amazon Bedrock frente a SageMaker
Si necesitas…Piensa en…Por qué
Consumir un FM existente mediante API con poca infraestructuraAmazon BedrockAcceso administrado a FMs, Knowledge Bases, Agents y Guardrails.
Construir, entrenar y desplegar un modelo ML propioAmazon SageMakerMayor control sobre datos, entrenamiento y endpoints; también más complejidad.
ML sin código para usuario de negocioSageMaker CanvasConstruir predicciones sin desarrollar código.
Trampa: Bedrock no es la opción por defecto para todo lo que se llame IA; SageMaker encaja cuando hay que construir o entrenar ML propio.
Prompt engineering, RAG y fine-tuning
  • Zero-shot: pedir una tarea sin ejemplos.
  • Few-shot: agregar ejemplos de entrada/salida para guiar formato o estilo.
  • RAG: recuperar documentos relevantes y agregarlos al contexto antes de generar. Da información propia/actualizada sin cambiar el modelo.
  • Fine-tuning: adaptar persistentemente el comportamiento del modelo usando datos de entrenamiento; requiere más tiempo, datos y costo.
  • Agents: permiten al FM ejecutar pasos y usar herramientas/APIs para completar una tarea.
Pista: “chatbot debe responder usando documentos internos que cambian” → RAG / Bedrock Knowledge Bases. “el modelo debe adoptar persistentemente un estilo o tarea específica” → fine-tuning puede ser apropiado.
Elegir un modelo fundacional

No existe “el mejor modelo” en abstracto. Compara precisión para tu tarea, costo por token, latencia, ventana de contexto y modalidades admitidas (por ejemplo, texto e imagen). Un modelo más grande no siempre es la solución más costo-efectiva.

Dominio 4 · IA responsable 14%

Una solución de IA útil debe ser también justa, explicable, segura y supervisable. En decisiones de alto impacto, una persona debe poder revisar o intervenir.

PrincipioPregunta para entenderloHerramienta o práctica
Equidad¿Perjudica injustamente a un grupo?Revisar sesgos en datos y resultados.
Explicabilidad¿Podemos explicar por qué decidió eso?SageMaker Clarify ayuda a detectar sesgo y explicar predicciones.
Transparencia¿La persona entiende capacidades y límites?Model cards y comunicación clara.
Robustez¿Funciona ante datos variados o inesperados?Pruebas, monitoreo y validación.
Control humano¿Alguien puede revisar, corregir o detener?Human-in-the-loop en decisiones sensibles.
Pista: “necesito detectar sesgo y explicar una predicción de ML” → SageMaker Clarify. “necesito bloquear contenido o PII en un FM” → Bedrock Guardrails.

Dominio 5 · Seguridad, cumplimiento y gobernanza 14%

  • IAM: aplica mínimo privilegio a quien invoca Bedrock, usa SageMaker o lee datos.
  • Cifrado: protege datos en reposo y en tránsito; revisa también quién puede usar la clave.
  • CloudTrail: registra quién hizo una acción y cuándo. CloudWatch observa métricas y operación.
  • Bedrock Guardrails: filtros/políticas sobre entradas y salidas, incluidos temas no permitidos y PII.
  • Prompt injection: un usuario intenta que el modelo ignore instrucciones o revele información. Usa límites de acceso, validación y guardrails.
  • Data poisoning: datos de entrenamiento manipulados degradan o sesgan el modelo. Gobierna procedencia y calidad de los datos.
Trampa: un guardrail reduce riesgos de contenido; no sustituye IAM, cifrado, validación de salida ni una política de datos.
