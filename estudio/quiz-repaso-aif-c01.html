Método para responder rápido: identifica primero qué quiere hacer el escenario: generar, recuperar, actuar, explicar, monitorear, etiquetar, traducir o evaluar. Luego busca la palabra clave y descarta servicios que solo “se parecen”.

1. Generative AI, Foundation Models y LLMs

Generative AI

Aprende patrones de datos existentes y crea contenido nuevo: texto, imágenes, audio, video, código o música. Regla: Generative AI no solo analiza, genera.

Foundation Model vs LLM

Foundation Model es la categoría amplia. Un LLM es un tipo de Foundation Model enfocado principalmente en lenguaje. Memoriza: LLM ⊂ Foundation Models.

Ventajas típicas

Productividad, automatización, personalización, innovación, investigación acelerada y generación de datos sintéticos.

2. Cómo aprenden los modelos

Self-supervised learning

Es común en el pre-training de Foundation Models. El propio dato genera señales o etiquetas implícitas sin etiquetado humano masivo.

Supervised learning

Usa ejemplos etiquetados. En el contexto visto para AIF-C01, el fine-tuning se asocia a supervised learning.

Unsupervised learning

Busca patrones y relaciones sin labels explícitos.

Reinforcement learning

Un agente interactúa con un entorno, toma acciones y recibe rewards o penalties. Aprende una policy para maximizar cumulative reward.

3. Reinforcement Learning

Conceptos

Agent, environment, state, action, reward, cumulative reward y policy.

Exploration vs exploitation

Exploration = probar acciones nuevas. Exploitation = usar acciones conocidas que ya funcionan.

Pista de examen

Feedback continuo + rewards/penalties + mejora basada en interacción → Reinforcement Learning.

Chatbot que mejora con feedback

Si clientes entregan feedback positivo/negativo y eso se usa como reward para optimizar respuestas, la respuesta esperada es RL.

4. Transfer Learning

Definición

Reutiliza conocimiento aprendido en una tarea o modelo para mejorar una tarea nueva pero relacionada.

Pasos típicos

Seleccionar un modelo preentrenado, conservar o congelar capas útiles, reemplazar/agregar capas específicas y entrenar para el nuevo dominio o tarea.

No confundir

Incremental training actualiza el mismo modelo con nuevos datos. Transfer learning reutiliza conocimiento previo para otra tarea relacionada.

Pista

Pre-trained model + reuse knowledge + new related task → Transfer Learning.

5. Transformers

Self-attention

Determina qué partes del texto son relevantes entre sí.

Contextual embeddings

La representación de una palabra depende del contexto.

Multi-head attention

Varias cabezas aprenden relaciones diferentes en paralelo.

Positional encoding

Aporta información sobre el orden de los tokens.

6. Tokens y Context Window

Token

Unidad de texto procesada por el modelo. Puede ser una palabra, parte de una palabra, puntuación o fragmento.

Context Window

Máximo de tokens que el modelo puede considerar simultáneamente. Prompt + historial + documentos RAG + salida consumen contexto.

Pista

Maximum amount of text the model can consider at once → Context Window.

7. Temperature, Top K, Top P y Stop Sequences

Temperature

Controla aleatoriedad/creatividad. Baja = más determinista. Alta = más diversa.

Top K

Controla el número de candidatos para el siguiente token. K = cantidad.

Top P

Controla el porcentaje acumulado de probabilidad considerado. P = probabilidad.

Stop sequences

Secuencias que hacen que el modelo deje de generar más tokens.

Trampa

number of candidates → Top K. percentage of most-likely candidates → Top P.

8. Prompt Engineering

Estructura de un buen prompt

Instructions + Context + Input data + Output Indicator. Regla: tarea + contexto + datos + formato.

Zero-shot

No incluye ejemplos.

One-shot

Incluye un ejemplo.

Few-shot

Incluye varios ejemplos input + output esperado. Para intent classification: user query + correct intent.

Costo

Más ejemplos suelen significar más input tokens; si el objetivo es bajar costo en Bedrock, acorta prompts y ejemplos.

9. RAG, embeddings y vector search

RAG

Recupera información externa relevante y la agrega al contexto antes de que el LLM genere la respuesta.

Embeddings

Representaciones numéricas usadas para comparar similitud semántica.

OpenSearch

Indexing, full-text search, similarity search, vector search y relevance ranking.

RAG vs Fine-tuning

Conocimiento privado o actualizado frecuentemente, PDFs y catálogos → RAG. Comportamiento/tarea específica → Fine-tuning.

Hallucinations

RAG ayuda a reducirlas al fundamentar respuestas en fuentes externas relevantes.

10. Knowledge Bases for Amazon Bedrock

Definición

Capacidad fully managed para implementar un flujo RAG end-to-end.

Qué gestiona

Ingestion, chunking, embeddings, vector store, retrieval y prompt augmentation.

Vector DB

Si no tienes una vector database, puede crear un Amazon OpenSearch Serverless vector store.

Pista

Fully managed RAG + Bedrock + proprietary data → Knowledge Bases for Amazon Bedrock.

11. Agents for Amazon Bedrock

Definición

Permiten crear agentes autónomos o semi-autónomos que orquestan Foundation Models, datos, aplicaciones y conversaciones.

Qué hacen

Entienden solicitudes, dividen tareas en pasos, recopilan información, consultan fuentes, invocan APIs y ejecutan acciones.

Knowledge Base vs Agent

Knowledge Bases retrieve. Agents reason and act.

Pista

Automate tasks + multi-step workflow + call APIs + take actions → Agents for Amazon Bedrock.

12. Amazon Bedrock: personalización

Fine-tuning

Usa labeled data. Especializa el modelo para una tarea o comportamiento específico.

Continued Pre-Training

Usa unlabeled domain data. Amplía conocimiento, terminología y contexto del dominio.

Domain expert

Domain Adaptation Fine-Tuning y Continued Pre-Training pueden complementarse.

Provisioned Throughput

Custom models pueden requerir capacidad provisionada para ejecución.

13. Amazon Bedrock: seguridad y auditoría

Guardrails

Mask oculta/redacta PII o información sensible. Block bloquea contenido o solicitudes.

Model Invocation Logging

Registra requests, responses y metadata. Puede enviar logs a CloudWatch Logs y/o S3. Está deshabilitado por defecto.

Watermark detection

Se usa para identificar ciertas imágenes generadas por modelos compatibles, no para RAG ni para agentes.

14. Amazon Bedrock: pricing y costo

On-Demand

Ideal para uso incierto o variable, experimentación y sin compromisos largos. Pay for what you use.

Provisioned Throughput

Adecuado para cargas estables/predecibles y capacidad garantizada.

Batch

Procesamiento no inmediato de grandes conjuntos de prompts; puede ser más económico en escenarios compatibles.

Tokens y costo

En modelos de texto, input/output tokens impactan el costo. Reducir tokens reduce gasto.

Distractores

Spot Instances y Reserved Instances son conceptos de EC2, no modelos de pricing de Bedrock.

15. Amazon Q

Amazon Q Developer

Asistente generativo para software development y AWS. Está powered by Amazon Bedrock.

Amazon Q Business

Asistente empresarial que puede combinar LLM + RAG para responder usando conocimiento interno.

Q vs Bedrock

Q = asistente listo. Bedrock = plataforma para construir aplicaciones GenAI y elegir FMs.

Pista

Amazon Q Business workflow → LLM + RAG.

16. SageMaker JumpStart, Canvas, Clarify, MLflow, Dashboard, Monitor, Ground Truth

JumpStart

Hub de ML con modelos preentrenados, FMs, soluciones preconstruidas, comparación y personalización.

Canvas

No-code ML mediante interfaz visual.

Clarify

Bias detection y explainability. Usa SHAP y feature attribution.

MLflow

Track, organize, analyze y compare ML experiments, runs, métricas, parámetros y versiones.

Model Dashboard

Vista central de modelos desplegados, endpoints y uso.

Model Monitor

Monitorea calidad y comportamiento en producción, incluido drift.

Ground Truth

Crea datasets etiquetados de alta calidad con workforce humana y automatización.

Feature Store

Repositorio para almacenar, compartir y gestionar features de ML.

17. Explainability: SHAP vs PDP

Shapley values / SHAP

Explicación local. Cuantifica cuánto contribuyó cada feature a una predicción específica.

Partial Dependence Plot

Explicación global. Muestra el efecto marginal de una feature sobre las predicciones a nivel de dataset.

Pista

¿Por qué ESTE caso? → SHAP. ¿Cómo afecta esta feature EN GENERAL? → PDP.

18. Interpretability vs Explainability

Interpretability

El modelo es comprensible por diseño.

Decision Trees

Muy interpretables. Permiten seguir un camino de decisiones y ver qué features influyeron.

Explainability

Usa técnicas adicionales para explicar modelos complejos, por ejemplo SHAP, PDP o SageMaker Clarify.

Pista

Transparent, easy to visualize decision path, interpretable by design → Decision Tree.

19. Model Inference vs Model Evaluation

Inference

Input/prompt → modelo → output. Inference = generar.

Evaluation

Mide y compara outputs/modelos para determinar cuál se adapta mejor al use case. Evaluation = medir/juzgar.

20. SageMaker Inference

Real-time

Necesitas respuesta inmediata.

Asynchronous

Puedes esperar; se encola y procesa después. Útil para payloads grandes o procesamiento largo.

Batch Transform

Procesa un dataset completo como trabajo por lotes.

Serverless

Tráfico intermitente o impredecible sin administrar servidores.

23. Overfitting, Data Augmentation y Bias

Overfitting

Muy bueno con training data, malo con datos nuevos. Soluciones: regularization, dropout, early stopping, tuning, más datos.

Data augmentation

Genera o incorpora ejemplos adicionales para aumentar diversidad y representación.

Sampling bias

La muestra no representa bien la población. Grupos overrepresented o underrepresented.

Measurement bias

Problema en cómo se midieron/capturaron los datos.

Observer bias

Subjetividad humana en observación o etiquetado.

Confirmation bias

Se favorece evidencia que confirma creencias previas.

24. Responsible AI y riesgos

Hallucination

Respuesta plausible y convincente, pero falsa o fabricada.

Plagiarism

Contenido no original presentado como propio.

Bias

Resultados sistemáticamente injustos o desbalanceados.

Misinterpretation

El significado o intención se interpreta incorrectamente.

25. Evaluación de modelos

Classification

Confusion Matrix, Accuracy, Precision, Recall y F1.

Confusion Matrix

Muestra true positives, true negatives, false positives y false negatives; permite ver qué clases se confunden.

Regression

MAE, MSE y RMSE para valores continuos.

Correlation Matrix

Analiza relaciones entre variables; no evalúa directamente desempeño de clasificación.

29. Tokens, embeddings y representaciones

Tokens

Son las unidades discretas de texto que procesa el modelo: palabras, sub-palabras, caracteres o signos.

Embeddings

Son representaciones numéricas densas de tokens, palabras, frases u otros datos para capturar significado y similitud.

Word2Vec

Genera embeddings estáticos: una palabra suele mantener el mismo vector aunque cambie el contexto.

BERT

Genera embeddings contextuales. La misma palabra puede tener representaciones distintas según la frase.

PCA

Técnica de reducción de dimensionalidad. Simplifica datos de alta dimensión conservando la mayor varianza posible.

SVD

Descompone matrices y puede usarse para compresión y representaciones latentes.

30. Métricas por tipo de tarea

BLEU

Métrica clásica para evaluar traducción automática comparando la salida con una o más traducciones de referencia.

ROUGE

Se usa principalmente para evaluar resúmenes automáticos comparando solapamiento con resúmenes de referencia.

Classification

Accuracy, Precision, Recall, F1 y Confusion Matrix.

Regression

MAE, MSE y RMSE.

Pista

Translation → BLEU. Summarization → ROUGE.

BERTScore

Evalúa similitud semántica con embeddings contextuales; puede aparecer como alternativa más semántica.

31. Sentiment Analysis en AWS

Amazon Comprehend

Servicio especializado en NLP para sentiment, entities, key phrases y language detection.

Amazon Bedrock

También puede realizar sentiment analysis usando Foundation Models con prompts o personalización.

Pista

Written customer reviews + sentiment → Comprehend. Si piden dos opciones y aparece Bedrock, Comprehend + Bedrock.

Categorías

Comprehend puede devolver Positive, Negative, Neutral o Mixed.

32. AWS Shared Responsibility Model

AWS: security OF the cloud

AWS protege infraestructura física, hardware, data centers, red global, Regions, Availability Zones y Edge Locations.

Customer: security IN the cloud

El cliente gestiona datos, IAM, accesos, aplicaciones, configuraciones y controles de seguridad según el servicio.

Regla

AWS = OF the cloud. Customer = IN the cloud.

Pista

Physical infrastructure → AWS. Customer data / IAM / permissions → Customer.

33. Prompting adicional

Negative prompting

Indica explícitamente qué debe evitar el modelo: marcas, temas, palabras o comportamientos.

Chain-of-thought

Descompone un problema complejo en pasos lógicos intermedios.

Tree-of-thought

Explora múltiples caminos posibles y evalúa alternativas.

Self-refine

El modelo genera una respuesta, la critica y la mejora iterativamente.

Generated knowledge

Primero genera hechos relevantes y luego responde usando ese conocimiento.

Directional stimulus

Usa pistas o keywords para guiar la salida deseada.

34. Exploratory Data Analysis (EDA)

EDA

Fase para explorar y entender los datos con estadísticas, visualizaciones, patrones, anomalías y outliers antes de modelar.

Data Preparation

Limpia y transforma datos: missing values, duplicates, encoding y preprocessing.

Regla

Preparation limpia. EDA entiende. Evaluation mide.

Pista

Calculate statistics + visualize trends + identify patterns → EDA.

35. Supervised Learning: ejemplos

Linear Regression

Supervised learning para predecir valores continuos.

Neural Networks

Pueden entrenarse de forma supervisada con datos etiquetados para clasificación o regresión.

Otros ejemplos

Logistic Regression y Decision Trees también son técnicas supervisadas típicas.

No confundir

Clustering y Association Rule Learning son unsupervised.

36. AWS Global Infrastructure

AWS Region

Cada Region tiene un mínimo de tres Availability Zones.

Availability Zone

Cada AZ contiene uno o más data centers discretos con energía, red y conectividad redundantes.

Jerarquía

Region → Availability Zones → Data Centers.

Edge Locations

No forman parte de la definición de una AZ; sirven para acercar servicios y contenido a usuarios finales.

37. Hyperparameters: epochs, learning rate, batch size y regularization

Epochs

Una epoch es una pasada completa por todo el dataset. Más epochs pueden mejorar aprendizaje hasta cierto punto.

Learning rate

Define el tamaño de los ajustes en los pesos durante entrenamiento.

Batch size

Cuántos ejemplos se procesan antes de actualizar los pesos.

Regularization

Penaliza complejidad para reducir overfitting.

Pista

Needs more opportunities to learn from training data → increase epochs.

Advertencia

Demasiados epochs pueden causar overfitting; conviene observar validation performance.
