First: what AIF-C01 actually tests

This is a foundational exam: it does not ask you to write code or calculate metrics. It asks you to understand what AI can do, what its risks are, and which AWS service best fits a business case.

  1. Identify the data: text, image, audio, document, purchase history, or labeled data?
  2. Identify the task: classify, extract, translate, recommend, forecast, converse, or generate content.
  3. Pick the level of control: ready-to-use AI service, Bedrock for generative AI, or SageMaker to build/train your own ML.
  4. Check the risks: bias, hallucinations, privacy, security, and human oversight.
Mental map: use case → type of AI → AWS service. Example: "extract fields from scanned invoices" → document → extraction → Amazon Textract.

Learning types and lifecycle
  • Supervised: data with a known answer. "These images already say cat/dog"; the model learns to classify.
  • Unsupervised: unlabeled data; looks for groupings or patterns. Example: segmenting customers by behavior.
  • Reinforcement: learns through rewards and penalties. Example: an agent that improves by playing.
  • ML lifecycle: business problem → data → preparation → training → evaluation → deployment → monitoring. If real-world data changes and the result gets worse, that is drift.
Hint: "predict a price using historical examples with a real price" → supervised learning. "group customers with no prior categories" → unsupervised.
Metrics you need to recognize
  • Accuracy: total percentage of correct predictions.
  • Precision: of what the model flagged as positive, how many actually were. Matters when a false positive is costly.
  • Recall: of all the real positives, how many it found. Matters when letting a positive slip through is dangerous, like fraud or a disease.
  • F1: balance between precision and recall.
Do not memorize formulas: identify the cost of each type of error. In fraud, it usually matters more not to miss real fraud cases: high recall.

Domain 2 · Fundamentals of Generative AI 24%

The building blocks of a generative application
  • Foundation model (FM): large pretrained model that serves many tasks.
  • LLM: an FM specialized in language.
  • Token: a fragment of text the model processes; affects cost, limits, and speed.
  • Context window: the maximum number of tokens the model considers at once.
  • Embedding: a numeric vector that represents meaning; lets you find similar content even without matching words.
  • Temperature: low = more consistent response; high = more variation/creativity.
Hint: "search documents by meaning" → embeddings and vector search; not a literal keyword search.
Limitations you should never forget
  • Hallucination: a made-up or incorrect response that sounds convincing.
  • Bias: unfair results due to data, model, or design.
  • Non-determinism: the same prompt can produce different responses.
  • Privacy: you should not send sensitive data without controls and authorization.
Generative AI is not a database: it can write fluently without its response being true. For up-to-date company data, think RAG and validation.

Trap: Bedrock is not the default option for everything called AI; SageMaker fits when you need to build or train your own ML.
Prompt engineering, RAG, and fine-tuning
  • Zero-shot: asking for a task with no examples.
  • Few-shot: adding input/output examples to guide format or style.
  • RAG: retrieve relevant documents and add them to the context before generating. Gives company-specific/up-to-date information without changing the model.
  • Fine-tuning: persistently adapt the model's behavior using training data; requires more time, data, and cost.
  • Agents: let the FM execute steps and use tools/APIs to complete a task.
  • Agentic AI: the agent plans, decides which tool to use, and executes several steps autonomously. Amazon Bedrock AgentCore is the managed platform for taking these agents to production (memory, identity, MCP gateway); Strands Agents and Kiro are AWS's SDK and agentic IDE for building them.
  • Model Distillation, Prompt Management, and LLM-as-a-Judge: distillation transfers knowledge from a large model to a smaller, cheaper one; Prompt Management versions and tests prompts without touching the code; LLM-as-a-Judge uses one model to evaluate another at scale.
Hint: "chatbot must answer using internal documents that change" → RAG / Bedrock Knowledge Bases. "the model must persistently adopt a specific style or task" → fine-tuning may be appropriate. "the system must execute several steps and decide for itself what to do" → Agentic AI with Bedrock AgentCore.
Choosing a foundation model

There is no "best model" in the abstract. Compare accuracy for your task, cost per token, latency, context window, and supported modalities (for example, text and image). A bigger model is not always the most cost-effective solution.

Domain 4 · Responsible AI 14%

A useful AI solution must also be fair, explainable, safe, and supervisable. In high-impact decisions, a person must be able to review or intervene.

PrincipleQuestion to understand itTool or practice
FairnessDoes it unfairly harm a group?Review bias in data and results.
ExplainabilityCan we explain why it decided that?SageMaker Clarify helps detect bias and explain predictions.
TransparencyDoes the person understand the capabilities and limits?Model cards and clear communication.
RobustnessDoes it work with varied or unexpected data?Testing, monitoring, and validation.

Domain 5 · Security, compliance, and governance 14%

  • IAM: apply least privilege to whoever invokes Bedrock, uses SageMaker, or reads data.
  • Encryption: protects data at rest and in transit; also check who can use the key.
  • CloudTrail: logs who did an action and when. CloudWatch watches metrics and operations.
  • Bedrock Guardrails: filters/policies on inputs and outputs, including disallowed topics and PII.
  • Prompt injection: a user tries to get the model to ignore instructions or reveal information. Use access limits, validation, and guardrails.
  • Data poisoning: manipulated training data degrades or biases the model. Govern data provenance and quality.
  • Grounding and Automated Reasoning checks: the contextual grounding check in Guardrails blocks responses not backed by a supplied source; Automated Reasoning checks mathematically verify that the response complies with business rules encoded as formal logic.
Trap: a guardrail reduces content risks; it does not replace IAM, encryption, output validation, or a data policy.
