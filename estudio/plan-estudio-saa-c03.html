Pares de decision criticos - referencia rapida
ALB vs NLB vs Gateway Load Balancer
ALBCapa 7 (HTTP/HTTPS), routing por path o host, ideal para microservicios y contenedores
VS
NLBCapa 4 (TCP/UDP), latencia ultra baja, IP estatica, millones de requests por segundo
VS
Gateway Load BalancerCapa 3, para insertar appliances de terceros (firewalls, IDS/IPS) de forma transparente
RDS vs Aurora vs DynamoDB
RDSRelacional administrado (MySQL, PostgreSQL, etc.), control cercano al motor original
VS
AuroraRelacional nativo de AWS, mayor performance y replicas mas rapidas, Global Database
VS
DynamoDBNoSQL clave-valor, escala masiva, latencia de milisegundos de un solo digito
Reserved vs Savings Plans vs Spot
Reserved InstancesCompromiso 1-3 anos ligado a familia/tamano especifico de instancia EC2
VS
Savings PlansCompromiso de gasto en USD/hora, flexible entre EC2, Fargate y Lambda
VS
Spot InstancesHasta 90% de descuento, puede ser interrumpida, ideal para batch tolerante a fallos
S3 Storage Classes por patron de acceso
Standard / Intelligent-TieringAcceso frecuente o impredecible, sin penalidad de recuperacion
VS
Standard-IA / One Zone-IAAcceso poco frecuente pero rapido cuando se necesita
VS
Glacier (Instant / Flexible / Deep Archive)Archivo, de minutos a horas de recuperacion, el mas barato para retencion larga
Route 53: politicas de enrutamiento
Latency-basedEnruta a la region con menor latencia de red para el usuario
VS
GeolocationEnruta segun la ubicacion geografica real del usuario, no la latencia
VS
Weighted / FailoverDistribuye trafico por porcentaje fijo, o conmuta a un sitio de respaldo si el primario falla el health check
KMS vs Secrets Manager vs Parameter Store
KMSGestiona las llaves de cifrado en si (CMK), base de la encriptacion en AWS
VS
Secrets ManagerGuarda secretos (contrasenas, API keys) con rotacion automatica incorporada
VS
SSM Parameter StoreConfiguracion y parametros, puede guardar SecureString, sin rotacion nativa
CloudTrail vs Config vs CloudWatch
CloudTrailQuien hizo que llamada a la API y cuando, auditoria de acciones
VS
AWS ConfigQue configuracion tiene un recurso ahora y como cambio con el tiempo, compliance
VS
CloudWatchMetricas de rendimiento, logs de aplicacion y alarmas operativas
IAM User vs IAM Role vs Resource Policy
IAM UserIdentidad de largo plazo con credenciales propias, para personas o apps fijas
VS
IAM RoleIdentidad temporal que se asume, ideal para servicios de AWS o cross-account
VS
Resource PolicySe adjunta al recurso (ej. bucket S3), no al usuario, define quien puede acceder desde afuera
