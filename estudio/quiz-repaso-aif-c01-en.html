1. Generative AI, Foundation Models and LLMs

Generative AI

Learns patterns from existing data and creates new content: text, images, audio, video, code, or music. Rule: Generative AI doesn't just analyze, it generates.

Foundation Model vs LLM

Foundation Model is the broad category. An LLM is a type of Foundation Model focused mainly on language. Memorize: LLM ⊂ Foundation Models.

Typical advantages

Productivity, automation, personalization, innovation, accelerated research, and synthetic data generation.

2. How Models Learn

Self-supervised learning

Common in the pre-training of Foundation Models. The data itself generates implicit signals or labels without massive human labeling.

Supervised learning

Uses labeled examples. In the AIF-C01 context, fine-tuning is associated with supervised learning.

Unsupervised learning

Looks for patterns and relationships without explicit labels.

Reinforcement learning

An agent interacts with an environment, takes actions, and receives rewards or penalties. It learns a policy to maximize cumulative reward.

3. Reinforcement Learning

Concepts

Agent, environment, state, action, reward, cumulative reward, and policy.

Exploration vs exploitation

Exploration = trying new actions. Exploitation = using known actions that already work.

Exam hint

Continuous feedback + rewards/penalties + improvement based on interaction → Reinforcement Learning.

Chatbot that improves with feedback

If customers give positive/negative feedback and it's used as a reward to optimize responses, the expected answer is RL.

4. Transfer Learning

Definition

Reuses knowledge learned in one task or model to improve a new but related task.

Typical steps

Select a pre-trained model, keep or freeze useful layers, replace/add task-specific layers, and train for the new domain or task.

Don't confuse

Incremental training updates the same model with new data. Transfer learning reuses prior knowledge for another related task.

Hint

Pre-trained model + reuse knowledge + new related task → Transfer Learning.

5. Transformers

Self-attention

Determines which parts of the text are relevant to each other.

Contextual embeddings

A word's representation depends on context.

Multi-head attention

Multiple heads learn different relationships in parallel.

Positional encoding

Adds information about token order.

6. Tokens and Context Window

Token

Unit of text processed by the model. It can be a word, part of a word, punctuation, or a fragment.

Context Window

Maximum number of tokens the model can consider at once. Prompt + history + RAG documents + output all consume context.

Hint

Maximum amount of text the model can consider at once → Context Window.

7. Temperature, Top K, Top P and Stop Sequences

Temperature

Controls randomness/creativity. Low = more deterministic. High = more diverse.

Top K

Controls the number of candidates for the next token. K = quantity.

Top P

Controls the cumulative probability percentage considered. P = probability.

Stop sequences

Sequences that make the model stop generating more tokens.

Trap

number of candidates → Top K. percentage of most-likely candidates → Top P.

8. Prompt Engineering

Structure of a good prompt

Instructions + Context + Input data + Output Indicator. Rule: task + context + data + format.

Zero-shot

Includes no examples.

One-shot

Includes one example.

Few-shot

Includes several input + expected output examples. For intent classification: user query + correct intent.

Cost

More examples usually mean more input tokens; if the goal is to lower cost in Bedrock, shorten prompts and examples.

9. RAG, Embeddings and Vector Search

RAG

Retrieves relevant external information and adds it to the context before the LLM generates the response.

Embeddings

Numeric representations used to compare semantic similarity.

OpenSearch

Indexing, full-text search, similarity search, vector search, and relevance ranking.

RAG vs Fine-tuning

Private or frequently updated knowledge, PDFs, and catalogs → RAG. Specific behavior/task → Fine-tuning.

Hallucinations

RAG helps reduce them by grounding responses in relevant external sources.

10. Knowledge Bases for Amazon Bedrock

Definition

Fully managed capability for implementing an end-to-end RAG flow.

What it manages

Ingestion, chunking, embeddings, vector store, retrieval, and prompt augmentation.

Vector DB

If you don't have a vector database, it can create an Amazon OpenSearch Serverless vector store.

Hint

Fully managed RAG + Bedrock + proprietary data → Knowledge Bases for Amazon Bedrock.

11. Agents for Amazon Bedrock

Definition

Let you create autonomous or semi-autonomous agents that orchestrate Foundation Models, data, applications, and conversations.

What they do

They understand requests, break tasks into steps, gather information, consult sources, invoke APIs, and execute actions.

Knowledge Base vs Agent

Knowledge Bases retrieve. Agents reason and act.

Hint

Automate tasks + multi-step workflow + call APIs + take actions → Agents for Amazon Bedrock.

12. Amazon Bedrock: Customization

Fine-tuning

Uses labeled data. Specializes the model for a specific task or behavior.

Continued Pre-Training

Uses unlabeled domain data. Expands domain knowledge, terminology, and context.

Domain expert

Domain Adaptation Fine-Tuning and Continued Pre-Training can complement each other.

Provisioned Throughput

Custom models may require provisioned capacity to run.

13. Amazon Bedrock: Security and Auditing

Guardrails

Mask hides/redacts PII or sensitive information. Block blocks content or requests.

Model Invocation Logging

Logs requests, responses, and metadata. Can send logs to CloudWatch Logs and/or S3. Disabled by default.

Watermark detection

Used to identify certain images generated by compatible models, not for RAG or agents.

14. Amazon Bedrock: Pricing and Cost

On-Demand

Ideal for uncertain or variable usage, experimentation, and no long-term commitments. Pay for what you use.

Provisioned Throughput

Suited for stable/predictable workloads and guaranteed capacity.

Batch

Non-immediate processing of large sets of prompts; can be more cost-effective in compatible scenarios.

Tokens and cost

For text models, input/output tokens impact cost. Reducing tokens reduces spend.

Distractors

Spot Instances and Reserved Instances are EC2 concepts, not Bedrock pricing models.

17. Explainability: SHAP vs PDP

Shapley values / SHAP

Local explanation. Quantifies how much each feature contributed to a specific prediction.

Partial Dependence Plot

Global explanation. Shows a feature's marginal effect on predictions across the dataset.

Hint

Why THIS case? → SHAP. How does this feature affect predictions IN GENERAL? → PDP.

18. Interpretability vs Explainability

Interpretability

The model is understandable by design.

Decision Trees

Highly interpretable. Let you follow a decision path and see which features influenced it.

Explainability

Uses additional techniques to explain complex models, such as SHAP, PDP, or SageMaker Clarify.

Hint

Transparent, easy to visualize decision path, interpretable by design → Decision Tree.

19. Model Inference vs Model Evaluation

Inference

Input/prompt → model → output. Inference = generate.

Evaluation

Measures and compares outputs/models to determine which best fits the use case. Evaluation = measure/judge.

20. SageMaker Inference

Real-time

You need an immediate response.

Asynchronous

You can wait; it's queued and processed later. Useful for large payloads or long processing.

Batch Transform

Processes an entire dataset as a batch job.

Serverless

Intermittent or unpredictable traffic without managing servers.

23. Overfitting, Data Augmentation and Bias

Overfitting

Very good with training data, poor with new data. Solutions: regularization, dropout, early stopping, tuning, more data.

Data augmentation

Generates or adds additional examples to increase diversity and representation.

Sampling bias

The sample doesn't represent the population well. Groups are overrepresented or underrepresented.

Measurement bias

A problem in how the data was measured/captured.

Observer bias

Human subjectivity in observation or labeling.

Confirmation bias

Evidence that confirms prior beliefs is favored.

24. Responsible AI and Risks

Hallucination

A plausible, convincing response that is false or fabricated.

Plagiarism

Non-original content presented as one's own.

Bias

Systematically unfair or unbalanced results.

Misinterpretation

The meaning or intent is interpreted incorrectly.

25. Model Evaluation

Classification

Confusion Matrix, Accuracy, Precision, Recall, and F1.

Confusion Matrix

Shows true positives, true negatives, false positives, and false negatives; lets you see which classes get confused.

Regression

MAE, MSE, and RMSE for continuous values.

Correlation Matrix

Analyzes relationships between variables; does not directly evaluate classification performance.

29. Tokens, Embeddings and Representations

Tokens

The discrete units of text the model processes: words, sub-words, characters, or symbols.

Embeddings

Dense numeric representations of tokens, words, phrases, or other data used to capture meaning and similarity.

Word2Vec

Generates static embeddings: a word usually keeps the same vector even when context changes.

BERT

Generates contextual embeddings. The same word can have different representations depending on the sentence.

PCA

Dimensionality reduction technique. Simplifies high-dimensional data while preserving as much variance as possible.

SVD

Decomposes matrices and can be used for compression and latent representations.

30. Metrics by Task Type

BLEU

Classic metric for evaluating machine translation by comparing the output with one or more reference translations.

ROUGE

Mainly used to evaluate automatic summaries by comparing overlap with reference summaries.

Classification

Accuracy, Precision, Recall, F1, and Confusion Matrix.

Regression

MAE, MSE, and RMSE.

Hint

Translation → BLEU. Summarization → ROUGE.

BERTScore

Evaluates semantic similarity using contextual embeddings; may appear as a more semantic alternative.

32. AWS Shared Responsibility Model

AWS: security OF the cloud

AWS protects physical infrastructure, hardware, data centers, the global network, Regions, Availability Zones, and Edge Locations.

Customer: security IN the cloud

The customer manages data, IAM, access, applications, configurations, and security controls depending on the service.

Rule

AWS = OF the cloud. Customer = IN the cloud.

Hint

Physical infrastructure → AWS. Customer data / IAM / permissions → Customer.

33. Additional Prompting Techniques

Negative prompting

Explicitly states what the model should avoid: brands, topics, words, or behaviors.

Chain-of-thought

Breaks a complex problem into intermediate logical steps.

Tree-of-thought

Explores multiple possible paths and evaluates alternatives.

Self-refine

The model generates a response, critiques it, and improves it iteratively.

Generated knowledge

First generates relevant facts, then answers using that knowledge.

Directional stimulus

Uses hints or keywords to guide the desired output.

34. Exploratory Data Analysis (EDA)

EDA

Phase for exploring and understanding data through statistics, visualizations, patterns, anomalies, and outliers before modeling.

Data Preparation

Cleans and transforms data: missing values, duplicates, encoding, and preprocessing.

Rule

Preparation cleans. EDA understands. Evaluation measures.

Hint

Calculate statistics + visualize trends + identify patterns → EDA.

35. Supervised Learning: Examples

Linear Regression

Supervised learning for predicting continuous values.

Neural Networks

Can be trained in a supervised way with labeled data for classification or regression.

Other examples

Logistic Regression and Decision Trees are also typical supervised techniques.

Don't confuse

Clustering and Association Rule Learning are unsupervised.

36. AWS Global Infrastructure

AWS Region

Each Region has a minimum of three Availability Zones.

Availability Zone

Each AZ contains one or more discrete data centers with redundant power, networking, and connectivity.

Hierarchy

Region → Availability Zones → Data Centers.

Edge Locations

Not part of the definition of an AZ; they bring services and content closer to end users.

37. Hyperparameters: Epochs, Learning Rate, Batch Size and Regularization

Epochs

An epoch is one complete pass through the entire dataset. More epochs can improve learning up to a point.

Learning rate

Defines the size of the weight adjustments during training.

Batch size

How many examples are processed before updating the weights.

Regularization

Penalizes complexity to reduce overfitting.

Hint

Needs more opportunities to learn from training data → increase epochs.

Warning

Too many epochs can cause overfitting; it's worth watching validation performance.

How do Temperature, Top K and Top P differ when controlling randomness and diversity in model generation?

Temperature changes randomness in the probability distribution; Top K limits the number of candidate tokens; Top P limits candidates by cumulative probability mass.
