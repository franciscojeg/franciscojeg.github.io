0. Antes de empezar: cómo es este examen
Este es un examen de nivel Profesional, no fundacional: no pregunta "qué es un embedding", sino "dado este escenario de negocio con estas restricciones, qué arquitectura de AWS implementarías". AWS lanzó esta certificación en noviembre de 2025, así que es una de las más nuevas del catálogo, y cubre capacidades muy recientes como Bedrock AgentCore y el protocolo MCP.

1. Foundation Model Integration, Data Management y Compliance 31% del examen
El dominio más grande del examen. Cubre desde el diseño arquitectónico inicial de una solución GenAI hasta las bases de datos vectoriales y la ingeniería de prompts. Si dominas bien este dominio, tienes casi un tercio del examen resuelto.

1.1 Analizar requisitos y diseñar soluciones GenAI

La decisión de diseño más fundamental de todo el examen: FM API directa contra RAG. Cuando conectas tu aplicación directamente a la API de un modelo fundacional (por ejemplo, invocando Bedrock directamente), el modelo solo responde con lo que aprendió durante su entrenamiento. Cuando agregas una arquitectura RAG (documentos propios → embeddings → base vectorial → recuperación de contexto → prompt enriquecido → modelo), el modelo puede responder con información actualizada y específica de tu empresa. La pregunta clave para elegir entre ambas: ¿la respuesta depende de conocimiento privado o actualizado que el modelo no tiene? Si sí, necesitas RAG.
SubtemaQué cubrePrioridad
Diseños arquitectónicos para soluciones GenAI Diseñar un asistente RAG típico combinando Amazon Bedrock (modelo e invocación), API Gateway (exponer la app como API) y CloudWatch (observabilidad del flujo completo). Alta
Niveles de Proof of Concept (PoC) Distintos niveles de madurez de una prueba de concepto GenAI, desde experimentar en el Bedrock Playground o un notebook de SageMaker AI, hasta un PoC medible con métricas de CloudWatch antes de pasar a producción. Media
Componentes técnicos estandarizados Convertir patrones de invocación de Bedrock en componentes reutilizables mediante CloudFormation o CDK, evaluados contra el AWS Well-Architected Tool, y gestionando prompts de forma centralizada con Bedrock Prompt Management, para que distintos equipos no reinventen la rueda cada vez. Media

1.4 Diseñar e implementar soluciones de base de datos vectorial

Las tres arquitecturas de vector store en AWS, explicadas desde cero: una base de datos vectorial guarda embeddings (vectores numéricos que representan significado) para poder buscar "por significado" en vez de por palabra exacta. AWS ofrece tres formas principales de implementar esto:
  1. RAG gestionado con Amazon Bedrock Knowledge Bases: la opción más simple. Tú apuntas a tus documentos (por ejemplo en S3) y Bedrock gestiona automáticamente el chunking, los embeddings y la búsqueda vectorial por debajo.
  2. Arquitectura basada en OpenSearch: usas Amazon OpenSearch Service como motor de búsqueda vectorial, con más control sobre la configuración del índice y el algoritmo de búsqueda (como k-NN), a cambio de más trabajo de configuración.
  3. Patrón RDS/DynamoDB más vector store externo: mantienes tus datos transaccionales en una base relacional o NoSQL ya existente, y le agregas capacidad vectorial, por ejemplo con la extensión pgvector sobre Amazon Aurora PostgreSQL. Útil cuando necesitas combinar filtros relacionales estrictos (como metadatos clínicos) con búsqueda semántica en la misma consulta.
SubtemaQué cubrePrioridad
Frameworks de metadatos para mejor búsquedaDiseñar esquemas de metadatos (por ejemplo, categoría, fecha, departamento) que se guardan junto a cada embedding, para poder filtrar resultados antes o después de la búsqueda semántica.Media
Arquitecturas vectoriales de alto rendimientoOptimizar un vector store para escalar a millones de embeddings sin degradar la latencia de búsqueda.Media
Integración con sistemas de datos existentesConectar el vector store con fuentes de datos y sistemas de conocimiento que la empresa ya tiene, en vez de crear un silo de datos aislado.Baja
Mantenimiento y actualización de vector storesDiseñar sistemas para mantener los embeddings sincronizados cuando los documentos originales cambian, se agregan o se eliminan.Media

2. Implementation and Integration 26% del examen
El segundo dominio en peso, y el más nuevo conceptualmente: cubre IA agéntica (agentes que razonan y ejecutan acciones), el protocolo MCP y patrones de integración empresarial. Si el AIF-C01 no cubrió agentes en profundidad, este es el dominio donde te vas a topar con más terminología nueva.

2.1 Implementar soluciones de IA agéntica e integraciones de herramientas

Chain-of-Thought contra ReAct, la distinción central de este dominio: Chain-of-Thought (CoT) es una técnica de prompting donde le pides al modelo que "piense paso a paso" antes de responder, pero todo ocurre dentro de una sola llamada al modelo, sin que el modelo interactúe con el mundo exterior. ReAct (Reasoning and Acting) es distinto: es un verdadero bucle agéntico, donde el agente repite un ciclo de Thought (razona qué hacer), Action (decide qué herramienta invocar y con qué parámetros) y Observation (recibe el resultado de esa herramienta), repitiendo el ciclo hasta resolver el objetivo. Como este bucle es propenso a fallos y de larga duración, el examen apunta específicamente a AWS Step Functions como la forma robusta de implementarlo, en vez de manejarlo dentro de una sola función Lambda, que sería frágil.
Model Context Protocol (MCP), explicado en simple: es un protocolo estandarizado que separa al agente (el "cliente MCP") de las herramientas que invoca (el "servidor MCP"), como APIs o bases de datos. En vez de programar una integración a medida cada vez que un agente necesita usar una herramienta nueva, MCP define una forma común de conectarse, haciendo el ecosistema de herramientas más modular y reutilizable entre distintos agentes.
Orquestación multi-agente con Amazon Bedrock AgentCore: cuando un problema es demasiado complejo para un solo agente, se puede dividir el trabajo entre varios agentes especializados. AgentCore actúa como la capa de razonamiento y orquestación: recibe un objetivo complejo, lo descompone en sub-tareas, y las enruta a agentes especializados (por ejemplo, un "agente de investigación" y un "agente de redacción"), manteniendo el contexto de la sesión con un almacén como Amazon DynamoDB.

3. AI Safety, Security y Governance 20% del examen
Este dominio extiende los principios de IA responsable del AIF-C01 hacia controles técnicos concretos: guardrails, verificación de alucinaciones, cumplimiento normativo y trazabilidad.

3.1 Implementar controles de seguridad de entrada y salida

Guardrails contra Automated Reasoning Checks: los guardrails de Bedrock filtran contenido de entrada y salida según políticas (bloquear temas, filtrar PII, evitar toxicidad). Los automated reasoning checks van un paso más allá: verifican matemáticamente que una afirmación generada por el modelo sea consistente con reglas o hechos conocidos, útil en dominios de alta regulación donde una alucinación no puede simplemente "sonar razonable", sino que debe ser verificable, por ejemplo validando que una respuesta sobre reglas de cumplimiento normativo no contradiga la política real de la empresa.
SubtemaQué cubrePrioridad
Sistemas de seguridad de contenidoFiltrar contenido dañino, tóxico o fuera de política antes de que llegue al usuario final, típicamente con Bedrock Guardrails.Alta
Frameworks de mitigación en la salidaEstrategias para corregir o bloquear una respuesta ya generada antes de entregarla, cuando la validación previa no fue suficiente.Media
Sistemas de verificación para reducir alucinacionesAutomated reasoning checks y otras técnicas de verificación de hechos sobre las respuestas del modelo antes de entregarlas, especialmente en dominios regulados como finanzas o salud.Alta
Sistemas de seguridad en profundidad (defense-in-depth)Combinar múltiples capas de control (guardrails, validación de entrada, revisión humana, monitoreo) en vez de depender de un solo mecanismo de seguridad.Media
Detección de amenazas y defensa contra adversariosIdentificar y mitigar intentos de prompt injection, jailbreaking y otros ataques dirigidos específicamente a manipular el comportamiento del modelo.Alta

4. Operational Efficiency y Optimization para GenAI 12% del examen
Este dominio se trata de que la solución GenAI no solo funcione, sino que sea rápida y económica a escala. Domina especialmente quantization y distillation, y la diferencia entre optimizar costo y optimizar performance, porque a veces van en direcciones opuestas.

4.1 Implementar optimización de costos y eficiencia de recursos

Quantization contra Distillation, las dos técnicas de optimización más preguntadas: la quantization (cuantización) reduce la precisión numérica con la que se almacenan los pesos del modelo (por ejemplo, de 32 bits a 8 bits), haciendo el modelo más pequeño y rápido de ejecutar, con una pérdida de precisión generalmente pequeña. Es la técnica indicada cuando minimizar el costo de cómputo es el KPI principal, o cuando necesitas desplegar en un dispositivo con memoria limitada (cámaras, robots, edge). La distillation (destilación) entrena un modelo más pequeño ("estudiante") para imitar el comportamiento de un modelo grande ("maestro"), obteniendo un modelo más liviano que conserva buena parte de la capacidad del original.
SubtemaQué cubrePrioridad
Sistemas de eficiencia de tokensReducir el número de tokens enviados y recibidos por invocación (prompts más concisos, respuestas acotadas), ya que el costo de la mayoría de los modelos generativos se factura por token.Alta
Frameworks de selección de modelos costo-efectivosElegir el modelo más barato que aún cumpla el nivel de calidad requerido para la tarea, en vez de usar por defecto el modelo más grande disponible.Alta
Sistemas FM de alto rendimiento (costo)Aplicar quantization y distillation para reducir el costo de cómputo sin descartar el modelo por completo.Alta
Sistemas de caché inteligenteCachear respuestas a preguntas frecuentes o resultados de búsqueda vectorial repetidos, para evitar invocar el modelo o la base vectorial de nuevo cuando la respuesta ya se conoce.Media

5. Testing, Validation y Troubleshooting 11% del examen
El dominio más pequeño, pero con un concepto clave que no existe en exámenes tradicionales de AWS: cómo evaluar la calidad de algo tan subjetivo como una respuesta generada por un modelo.

5.1 Implementar sistemas de evaluación para GenAI

LLM-as-a-Judge, un concepto que no aparece en el AIF-C01: evaluar manualmente miles de respuestas generadas no escala. La técnica de LLM-as-a-Judge usa un segundo modelo de lenguaje, generalmente más grande o especializado, para calificar automáticamente las respuestas del primer modelo contra criterios definidos (precisión, relevancia, tono), acelerando la evaluación a gran escala sin depender solo de revisión humana.

6. Comparaciones críticas (memorizar sí o sí)
Estas son las distinciones que más se prestan a confusión en un examen de nivel profesional, donde varias opciones pueden sonar razonables a la vez.
ComparaciónPunto de distinción
FM API directa contra RAGResponder solo con el conocimiento de entrenamiento del modelo, contra enriquecer la respuesta con contexto recuperado de tus propios documentos en el momento de la consulta.
Chain-of-Thought contra ReActRazonamiento paso a paso dentro de una sola llamada al modelo, contra un bucle agéntico real que alterna entre pensar, actuar sobre herramientas externas y observar el resultado.
Model Context Protocol (MCP) contra integración a medidaUn protocolo estandarizado y reutilizable para que cualquier agente use cualquier herramienta, contra una integración construida específicamente para un solo caso, difícil de reutilizar.
Bedrock Guardrails contra Automated Reasoning ChecksFiltrar contenido de entrada y salida según políticas de contenido, contra verificar matemáticamente que una afirmación generada sea consistente con reglas o hechos conocidos.
Quantization contra DistillationReducir la precisión numérica de los pesos de un mismo modelo para hacerlo más liviano, contra entrenar un modelo nuevo y más pequeño que imite el comportamiento de uno más grande.
Fallback Model contra Circuit BreakerRedirigir automáticamente a un modelo secundario cuando el principal falla, contra dejar de invocar por completo un servicio que está fallando repetidamente para no saturarlo más.
Multi-Agent Orchestration contra un solo agente con herramientasDividir un objetivo complejo entre varios agentes especializados coordinados por un supervisor, contra un único agente que invoca varias herramientas por sí mismo.
Provisioned Throughput contra pago por token (on-demand)Capacidad reservada y garantizada para cargas constantes y predecibles, contra pago solo por lo que se consume, mejor para cargas variables.
Búsqueda léxica contra búsqueda vectorial contra búsqueda híbridaCoincidencia exacta de palabras, contra coincidencia por significado semántico, contra la combinación de ambas con reranking posterior para mejores resultados.
LLM-as-a-Judge contra evaluación humanaUn modelo evalúa automáticamente las respuestas de otro modelo a gran escala, contra personas revisando manualmente una muestra de respuestas.
Amazon Bedrock Knowledge Bases contra arquitectura vectorial en OpenSearch contra pgvector sobre Aurora/RDSRAG gestionado con configuración mínima, contra más control sobre el motor de búsqueda vectorial, contra combinar datos relacionales existentes con capacidad vectorial en la misma base de datos.

8. Checklist final de repaso

Conceptos fundamentales que este examen asume que ya dominas

  • Todo lo del AIF-C01: tokens, embeddings, RAG, fine-tuning, prompt engineering básico
  • La diferencia entre Bedrock y SageMaker AI, y cuándo se combinan ambos en una misma solución
  • Los principios generales de seguridad de AWS: IAM, KMS, VPC, aplicados ahora a IA

Conceptos nuevos específicos de este examen

  • Las tres arquitecturas de vector store: Knowledge Bases gestionado, OpenSearch, y RDS/DynamoDB más vector store externo
  • Chain-of-Thought contra ReAct, y por qué ReAct se implementa con Step Functions
  • Qué es el Model Context Protocol (MCP) y la diferencia entre cliente y servidor MCP
  • Qué hace Amazon Bedrock AgentCore en una arquitectura multi-agente
  • Guardrails contra Automated Reasoning Checks
  • Quantization contra Distillation, y cuándo usar cada una
  • LLM-as-a-Judge como método de evaluación a escala
  • Los patrones de resiliencia específicos de GenAI: Fallback Model, Multi-Region Inference, Circuit Breaker

Estrategia el día del examen

  • 75 preguntas en 180 minutos, con tipos de pregunta variados: opción múltiple, respuesta múltiple, ordenamiento, emparejamiento y casos de estudio
  • 750 de 1000 puntos para aprobar, con puntuación compensatoria entre dominios: no necesitas aprobar cada dominio por separado
  • Los escenarios son largos: identifica primero qué restricción de negocio es la prioritaria (costo, latencia, cumplimiento regulatorio, resiliencia) antes de evaluar las opciones
  • En preguntas de caso de estudio, las siguientes preguntas del mismo caso pueden dar pistas adicionales sobre el escenario; léelas en conjunto si es posible
  • Ante dos soluciones técnicamente correctas, prioriza la que use el servicio administrado (managed) sobre la que requiere más código o infraestructura propia, salvo que el enunciado pida explícitamente más control
Recuerda: por ser una certificación tan nueva, el volumen de simulacros de terceros y experiencias reportadas por otros candidatos todavía es limitado comparado con certificaciones más establecidas como el SAA-C03. Complementa este material con la documentación oficial de Bedrock AgentCore, Guardrails y el Exam Guide más reciente antes de presentarte.
