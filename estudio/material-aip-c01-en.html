0. Before you start: what this exam is like
This is a Professional-level exam, not a foundational one: it doesn't ask "what is an embedding", it asks "given this business scenario with these constraints, what AWS architecture would you implement". AWS launched this certification in November 2025, so it's one of the newest in the catalog, and it covers very recent capabilities like Bedrock AgentCore and the MCP protocol.

Exam codeAIP-C01
Questions75, combining multiple choice, multiple response, ordering, matching, and case-study questions (a scenario with 2 or more related questions)
Duration180 minutes
Score100 to 1000, with 750 as the minimum to pass, using a compensatory scoring model: you don't need to pass each domain separately, but you do need the total score
Cost300 USD per attempt, no limit on attempts, but a mandatory 14-day wait between attempts if you don't pass
PrerequisitesNone formal, though it's designed for people with at least 1 year of hands-on experience with Bedrock, SageMaker AI, and other generative AI tools

How to think about this exam versus AIF-C01: if you already studied AIF-C01 (foundational level), think of AIP-C01 as its hands-on continuation. AIF-C01 asked you "what is RAG?". This exam gives you a complete scenario, with business constraints, regulation, budget, and scale, and asks you to design, implement, secure, optimize, and debug the full solution. You'll see the same core concepts (RAG, fine-tuning, embeddings, prompt engineering) but taken into real production architectures: multiple regions, CI/CD, observability, governance, and multi-agent systems.
Note on currency: because this is a newly launched certification, the services and capabilities it covers (especially everything related to agentic AI, Bedrock AgentCore, and the MCP protocol) are evolving very fast. Always check the official Exam Guide and the latest Bedrock documentation before your exam.

1. Foundation Model Integration, Data Management and Compliance 31% of the exam
The largest domain in the exam. It covers everything from the initial architectural design of a GenAI solution to vector databases and prompt engineering. If you master this domain, you've got nearly a third of the exam solved.

1.1 Analyze requirements and design GenAI solutions

The most fundamental design decision in the whole exam: direct FM API vs. RAG. When you connect your application directly to a foundation model's API (for example, invoking Bedrock directly), the model can only respond with what it learned during training. When you add a RAG architecture (your own documents → embeddings → vector store → context retrieval → enriched prompt → model), the model can respond with up-to-date information specific to your company. The key question for choosing between the two: does the answer depend on private or up-to-date knowledge the model doesn't have? If so, you need RAG.
SubtopicWhat it coversPriority
Architectural designs for GenAI solutions Designing a typical RAG assistant combining Amazon Bedrock (model and invocation), API Gateway (exposing the app as an API), and CloudWatch (observability across the whole flow). High
Proof of Concept (PoC) maturity levels Different maturity levels of a GenAI proof of concept, from experimenting in the Bedrock Playground or a SageMaker AI notebook, to a measurable PoC with CloudWatch metrics before moving to production. Medium
Standardized technical components Turning Bedrock invocation patterns into reusable components via CloudFormation or CDK, evaluated against the AWS Well-Architected Tool, and centrally managing prompts with Bedrock Prompt Management, so different teams don't reinvent the wheel each time. Medium

1.4 Design and implement vector database solutions

The three vector store architectures in AWS, explained from scratch: a vector database stores embeddings (numeric vectors representing meaning) so you can search "by meaning" instead of by exact word. AWS offers three main ways to implement this:
  1. Managed RAG with Amazon Bedrock Knowledge Bases: the simplest option. You point it at your documents (for example, in S3) and Bedrock automatically handles chunking, embeddings, and vector search under the hood.
  2. OpenSearch-based architecture: you use Amazon OpenSearch Service as the vector search engine, with more control over index configuration and the search algorithm (like k-NN), in exchange for more configuration work.
  3. RDS/DynamoDB plus external vector store pattern: you keep your transactional data in an existing relational or NoSQL database and add vector capability to it, for example with the pgvector extension on Amazon Aurora PostgreSQL. Useful when you need to combine strict relational filters (like clinical metadata) with semantic search in the same query.

Metadata frameworks for better searchDesigning metadata schemas (for example, category, date, department) stored alongside each embedding, to filter results before or after semantic search.Medium
High-performance vector architecturesOptimizing a vector store to scale to millions of embeddings without degrading search latency.Medium
Integration with existing data systemsConnecting the vector store with data sources and knowledge systems the company already has, instead of creating an isolated data silo.Low
Vector store maintenance and updatesDesigning systems to keep embeddings in sync when the original documents change, are added, or are removed.Medium

2. Implementation and Integration 26% of the exam
The second-heaviest domain, and the newest conceptually: it covers agentic AI (agents that reason and execute actions), the MCP protocol, and enterprise integration patterns. If AIF-C01 didn't cover agents in depth, this is the domain where you'll run into the most new terminology.

2.1 Implement agentic AI solutions and tool integrations

Chain-of-Thought vs. ReAct, the central distinction in this domain: Chain-of-Thought (CoT) is a prompting technique where you ask the model to "think step by step" before answering, but it all happens within a single call to the model, without the model interacting with the outside world. ReAct (Reasoning and Acting) is different: it's a true agentic loop, where the agent repeats a cycle of Thought (reason about what to do), Action (decide which tool to invoke and with what parameters), and Observation (receive that tool's result), repeating the cycle until the goal is solved. Because this loop is failure-prone and long-running, the exam specifically points to AWS Step Functions as the robust way to implement it, instead of handling it inside a single Lambda function, which would be fragile.
Model Context Protocol (MCP), explained simply: it's a standardized protocol that separates the agent (the "MCP client") from the tools it invokes (the "MCP server"), such as APIs or databases. Instead of coding a custom integration every time an agent needs to use a new tool, MCP defines a common way to connect, making the tool ecosystem more modular and reusable across different agents.
Multi-agent orchestration with Amazon Bedrock AgentCore: when a problem is too complex for a single agent, the work can be split across several specialized agents. AgentCore acts as the reasoning and orchestration layer: it receives a complex goal, breaks it down into sub-tasks, and routes them to specialized agents (for example, a "research agent" and a "writing agent"), keeping the session context in a store such as Amazon DynamoDB.

3. AI Safety, Security and Governance 20% of the exam
This domain extends the responsible AI principles from AIF-C01 into concrete technical controls: guardrails, hallucination verification, regulatory compliance, and traceability.

3.1 Implement input and output security controls

Guardrails vs. Automated Reasoning Checks: Bedrock guardrails filter input and output content according to policies (blocking topics, filtering PII, avoiding toxicity). Automated reasoning checks go a step further: they mathematically verify that a claim generated by the model is consistent with known rules or facts, useful in highly regulated domains where a hallucination can't just "sound reasonable" but must be verifiable — for example, validating that a response about compliance rules doesn't contradict the company's actual policy.
SubtopicWhat it coversPriority
Content security systemsFiltering harmful, toxic, or out-of-policy content before it reaches the end user, typically with Bedrock Guardrails.High
Output mitigation frameworksStrategies to correct or block a response that's already been generated before delivering it, when upstream validation wasn't enough.Medium
Verification systems to reduce hallucinationsAutomated reasoning checks and other fact-verification techniques applied to the model's responses before delivery, especially in regulated domains like finance or healthcare.High
Defense-in-depth security systemsCombining multiple layers of control (guardrails, input validation, human review, monitoring) instead of relying on a single security mechanism.Medium
Threat detection and adversarial defenseIdentifying and mitigating prompt injection, jailbreaking, and other attacks specifically aimed at manipulating the model's behavior.High

4. Operational Efficiency and Optimization for GenAI 12% of the exam
This domain is about making sure the GenAI solution doesn't just work, but is fast and economical at scale. Focus especially on quantization and distillation, and the difference between optimizing for cost and optimizing for performance, because they sometimes pull in opposite directions.

4.1 Implement cost optimization and resource efficiency

Quantization vs. Distillation, the two most-tested optimization techniques: quantization reduces the numeric precision used to store the model's weights (for example, from 32 bits to 8 bits), making the model smaller and faster to run, with generally small accuracy loss. It's the right technique when minimizing compute cost is the main KPI, or when you need to deploy on a device with limited memory (cameras, robots, edge). Distillation trains a smaller ("student") model to imitate the behavior of a large ("teacher") model, producing a lighter model that retains much of the original's capability.
SubtopicWhat it coversPriority
Token efficiency systemsReducing the number of tokens sent and received per invocation (more concise prompts, bounded responses), since most generative models are billed per token.High
Cost-effective model selection frameworksChoosing the cheapest model that still meets the quality bar required for the task, instead of defaulting to the largest available model.High
High-performance (cost-optimized) FM systemsApplying quantization and distillation to reduce compute cost without discarding the model entirely.High
Intelligent caching systemsCaching responses to frequent questions or repeated vector search results, to avoid invoking the model or the vector store again when the answer is already known.Medium

4.2 Optimize application performance

SubtopicWhat it coversPriority

5. Testing, Validation and Troubleshooting 11% of the exam
The smallest domain, but with a key concept that doesn't exist in traditional AWS exams: how to evaluate the quality of something as subjective as a model-generated response.

5.1 Implement evaluation systems for GenAI

LLM-as-a-Judge, a concept that doesn't appear in AIF-C01: manually evaluating thousands of generated responses doesn't scale. The LLM-as-a-Judge technique uses a second language model, generally larger or specialized, to automatically score the first model's responses against defined criteria (accuracy, relevance, tone), speeding up evaluation at scale without relying solely on human review.
SubtopicWhat it coversPriority
Systematic model evaluation frameworksDefining objective, repeatable criteria to compare the performance of different models or versions of the same model.High

Deployment validation and quality assuranceVerifying that a new version of the system meets quality standards before replacing the production version.Medium
Systematic QA processesStandardizing the quality control process so it's repeatable on each new iteration of the system, not an ad hoc manual effort.Medium
Comprehensive evaluation for RAG and LLM-as-a-JudgeEvaluating not just the final response, but also the quality of what was retrieved from the vector store before reaching the model.High
Retrieval quality testingSpecifically measuring whether the vector search system is returning the correct, relevant chunks, regardless of how well the model responds afterward.High
Agent performance frameworksSpecifically evaluating whether an agent correctly completed a multi-step task, not just whether it generated coherent text.Medium
Comprehensive reporting systemsConsolidating evaluation results into clear reports for different audiences, from the technical team to the business.Low
Deployment validation systemsAutomating quality verification as part of the CI/CD pipeline, before a change reaches production.Medium

6. Critical comparisons (memorize, no excuses)
These are the distinctions most likely to cause confusion on a professional-level exam, where several options can sound reasonable at once.
ComparisonKey distinction
Direct FM API vs RAGAnswering only from the model's training knowledge, vs enriching the response with context retrieved from your own documents at query time.
Chain-of-Thought vs ReActStep-by-step reasoning within a single model call, vs a real agentic loop that alternates between thinking, acting on external tools, and observing the result.
Model Context Protocol (MCP) vs custom integrationA standardized, reusable protocol for any agent to use any tool, vs an integration built specifically for one case, hard to reuse.
Bedrock Guardrails vs Automated Reasoning ChecksFiltering input and output content against content policies, vs mathematically verifying that a generated statement is consistent with known rules or facts.
Quantization vs DistillationReducing the numeric precision of a single model's weights to make it lighter, vs training a new, smaller model that mimics the behavior of a larger one.
Fallback Model vs Circuit BreakerAutomatically redirecting to a secondary model when the primary one fails, vs stopping invocations entirely to a service that keeps failing so it isn't overloaded further.
Multi-Agent Orchestration vs a single agent with toolsSplitting a complex goal across several specialized agents coordinated by a supervisor, vs a single agent invoking multiple tools on its own.
Provisioned Throughput vs pay-per-token (on-demand)Reserved, guaranteed capacity for steady, predictable load, vs paying only for what you consume, better for variable load.
Lexical search vs vector search vs hybrid searchExact word matching, vs matching by semantic meaning, vs combining both with reranking afterward for better results.
LLM-as-a-Judge vs human evaluationA model automatically scores another model's responses at scale, vs people manually reviewing a sample of responses.
Amazon Bedrock Knowledge Bases vs a vector architecture on OpenSearch vs pgvector on Aurora/RDSManaged RAG with minimal configuration, vs more control over the vector search engine, vs combining existing relational data with vector capability in the same database.

8. Final review checklist

Foundational concepts this exam assumes you already know

  • Everything from AIF-C01: tokens, embeddings, RAG, fine-tuning, basic prompt engineering
  • The difference between Bedrock and SageMaker AI, and when the two are combined in the same solution
  • AWS's general security principles: IAM, KMS, VPC, now applied to AI

New concepts specific to this exam

  • The three vector store architectures: managed Knowledge Bases, OpenSearch, and RDS/DynamoDB plus an external vector store
  • Chain-of-Thought vs ReAct, and why ReAct is implemented with Step Functions
  • What the Model Context Protocol (MCP) is and the difference between an MCP client and server
  • What Amazon Bedrock AgentCore does in a multi-agent architecture
  • Guardrails vs Automated Reasoning Checks
  • Quantization vs Distillation, and when to use each
  • LLM-as-a-Judge as an evaluation method at scale
  • GenAI-specific resilience patterns: Fallback Model, Multi-Region Inference, Circuit Breaker

Exam-day strategy

  • 75 questions in 180 minutes, with varied question types: multiple choice, multiple response, ordering, matching, and case studies
  • 750 out of 1000 points to pass, with compensatory scoring across domains: you don't need to pass each domain individually
  • Scenarios are long: first identify which business constraint is the priority (cost, latency, regulatory compliance, resilience) before evaluating the options
  • In case-study questions, later questions on the same case can offer additional clues about the scenario; read them together when possible
  • When two solutions are technically correct, favor the one that uses the managed service over the one requiring more code or custom infrastructure, unless the question explicitly asks for more control
Keep in mind: because this is such a new certification, the volume of third-party practice exams and candidate-reported experiences is still limited compared to more established certifications like SAA-C03. Supplement this material with the official Bedrock AgentCore and Guardrails documentation, and the latest Exam Guide, before you sit the exam.
