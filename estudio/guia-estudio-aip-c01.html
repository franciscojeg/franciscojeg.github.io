Qué exige AIP-C01

No basta con invocar un modelo. Debes saber convertir un caso de negocio en una aplicación GenAI segura, observable, costo-eficiente y verificable.

  1. ¿El modelo ya sabe lo necesario? Si no, agrega datos actuales con RAG; si debe cambiar su comportamiento de fondo, considera personalización/fine-tuning.
  2. ¿Qué calidad se requiere? Define evaluación, criterios, datos de prueba y revisión humana cuando corresponda.
  3. ¿Qué puede fallar o ser abusado? Aplica controles a entradas, recuperación, herramientas y salidas.
  4. ¿Cómo se opera? Mide tokens, latencia, errores, calidad de retrieval y costo.
Patrón de examen: requisito → arquitectura → control → métrica. Ejemplo: “respuestas con documentos internos actuales y citas” → RAG + vector store/Knowledge Base + control de acceso por documento + evaluación de recuperación.

Dominio 1 · FM, datos y cumplimiento 31% · mayor peso

API directa, RAG o fine-tuning
NecesidadElección principalPor qué
Generar, resumir o clasificar con conocimiento generalInvocación directa de FMMenor complejidad: prompt + modelo apropiado.
Responder con documentos propios, actualizados y citablesRAGRecupera contexto relevante en tiempo de consulta; no cambia los pesos del modelo.
Cambiar de forma persistente estilo, formato o habilidad específicaFine-tuning/personalizaciónAdapta el modelo; implica datos, lifecycle, evaluación y mayor costo.
Trampa: no uses fine-tuning solo para que el modelo “conozca” documentos que cambian. RAG suele ser más rápido de actualizar y mantener.
RAG explicado como un flujo de producción

Ingesta: documentos → validación/limpieza → segmentación (chunking) → embeddings → índice vectorial. Consulta: pregunta → embedding → búsqueda → opcional filtro, búsqueda híbrida y reranking → contexto → FM → respuesta con fuente.

  • Chunking: fragmentos muy grandes meten ruido y elevan tokens; muy pequeños pierden contexto. Ajusta a la estructura y tipo de documento.
  • Metadata: atributos como tenant, región, fecha y permiso. Sirve para filtrar antes de recuperar y evita fuga entre usuarios.
  • Búsqueda híbrida: combina coincidencia semántica y palabras clave. Reranking: reordena resultados para mejorar relevancia.
  • Actualización: CDC/eventos o refresh programado; monitoriza la ingesta, el índice y la calidad de recuperación.
Pista: “filtrar resultados por departamento o usuario” → metadata + control de acceso en retrieval, no solo un prompt que diga “no muestres datos”.
Elegir y operar modelos fundacionales
  • Selecciona por calidad en tu caso de uso, latencia, costo por token, ventana de contexto, modalidad y requisitos de región/cumplimiento.
  • Diseña fallback a otro modelo y reintentos con backoff para resiliencia. La ruta alternativa debe evaluarse, no solo existir.
  • Usa Bedrock para consumir modelos y capacidades administradas; usa SageMaker cuando el ciclo de vida y despliegue de modelo requieren mayor control.

Dominio 2 · Implementación e integración 26%

Agentes, herramientas y humanos
  • Agente: FM que elige pasos y usa herramientas para completar un objetivo. No es simplemente un chatbot.
  • Herramienta: función/API con contrato claro, validación de entrada y permisos mínimos. Lambda es común para encapsular una acción.
  • Human-in-the-loop: una persona aprueba o corrige acciones de alto impacto antes de ejecutarlas.
  • Step Functions: orquesta estados, reintentos, esperas y aprobaciones; no delegues todo el control al FM.
  • MCP: patrón/protocolo para dar a modelos un acceso consistente a herramientas y contexto; gobierna qué herramientas se exponen.
Trampa: un modelo nunca debe recibir permisos amplios porque “necesita autonomía”. Limita herramientas, acciones y datos por role/policy.
Integración resiliente y empresarial
RequisitoPatrón AWS
Respuesta larga y sensación de menor esperaStreaming de respuesta; UI consume tokens progresivamente.
Trabajo lento o gran volumenAsíncrono: SQS/buffer + workers; notificar resultado al finalizar.
Falla o throttling de FMRetry con exponential backoff, circuit breaker, fallback model.
Acceso privado a serviciosVPC endpoints / PrivateLink, IAM y cifrado.
Entrega repetibleIaC (CloudFormation/CDK) + CI/CD + gates de evaluación.
Pista: “mínimo cambio, desacoplar picos de solicitudes de inferencia” → SQS y procesamiento asíncrono. “respuesta conversacional inmediata” → streaming.
Prompts como componente de software

Versiona prompts, usa plantillas con variables y pruébalos con un conjunto de casos. Un prompt es configuración de producción: requiere revisión, trazabilidad y rollback. Prompt Flows permite orquestar etapas; Prompt Management ayuda a centralizar versiones.

Defensa en profundidad
CapaQué protegeEjemplo
Antes de inferirEntradas maliciosas, tóxicas o PIIValidación, normalización, filtros y Guardrails.

  • Prompt injection/jailbreak: intento de alterar instrucciones o exfiltrar datos. Trata el prompt del usuario como entrada no confiable.
  • PII: detecta, enmascara, limita retención y evita registrar datos sensibles sin necesidad.
  • Auditoría: CloudTrail para actividad API; logging estructurado con redacción de secretos/PII.
Responsabilidad y cumplimiento
  • Transparencia: comunica límites, muestra fuentes cuando se usa RAG y registra decisiones relevantes.
  • Equidad: prueba resultados con conjuntos representativos; no asumas que un modelo es neutral.
  • Gobernanza: model cards, data lineage, tags, SCPs y controles organizacionales.
  • Guardrails: filtran contenidos y PII, pero no reemplazan IAM, cifrado, evaluación ni validación de la aplicación.

Dominio 4 · Eficiencia y optimización 12%

Costo, latencia y throughput
  • Tokens: reducelos con prompts concisos, contexto relevante, límites de salida y resumen de historial. Más contexto no siempre mejora calidad.
  • Modelo: enruta tareas simples al modelo más económico; reserva modelos costosos para tareas que lo necesitan.
  • Caché: reutiliza resultados para consultas repetidas y evita invocaciones innecesarias; considera invalidez y privacidad.
  • Throughput: batch para trabajos no urgentes, concurrencia controlada, SQS como buffer y Provisioned Throughput cuando la demanda predecible justifica el compromiso.
  • RAG: mide recall/relevancia frente a latencia. Pre-filtrar metadata, ajustar índice y rerankear tienen trade-offs.
Pista: “reducir costo sin degradar respuestas repetidas” → caché. “carga estable, alta y predecible” → evalúa Provisioned Throughput.
Observabilidad que importa

Mide latencia end-to-end, tiempo de retrieval, tokens de entrada/salida, errores/throttling, costo, uso de throughput, calidad de recuperación, alucinaciones y drift de prompts/embeddings. CloudWatch concentra métricas y alarmas; X-Ray ayuda a encontrar qué tramo de la solicitud crea la latencia.

Dominio 5 · Testing, validación y troubleshooting 11%

Evalúa antes y después de desplegar
  • Crea un dataset de evaluación con casos normales, bordes, seguridad y respuestas esperadas/rúbrica.
  • Evalúa modelo, prompt, retrieval y agente por separado; si todo se prueba como una caja negra, no sabrás qué falló.
  • Usa evaluación automática, revisión humana y, cuando sea útil, LLM-as-a-judge con controles. Ninguno sustituye todos los demás.
  • Despliega gradualmente: canary/shadow, gates de calidad, monitoreo y rollback.
Pista: “resultado deficiente en RAG” → primero separa: ¿no recuperó el documento correcto o el FM no lo usó correctamente?
Diagnóstico sistemático
SíntomaPrimera hipótesis que debes comprobar

Comparaciones que deciden preguntas

ParDecisión rápida
RAG vs fine-tuningConocimiento externo/actualizable vs cambio persistente del comportamiento del modelo.
Bedrock vs SageMakerConsumo e integración administrada de FMs vs mayor control para ciclo ML/model deployment.
Guardrails vs IAMPolítica de contenido/PII vs autorización de acciones y recursos. Necesitas ambos.
Streaming vs asíncronoPercepción de respuesta rápida e interacción vs procesamiento largo/no urgente.
Vector-only vs búsqueda híbridaSimilitud semántica vs semántica + coincidencia de términos, útil para nombres/códigos exactos.
Fallback vs retryOtro modelo/ruta cuando la principal no sirve vs volver a intentar una falla transitoria.
