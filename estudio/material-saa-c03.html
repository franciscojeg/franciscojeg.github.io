0. Fundamentos que debes tener automatizados
Antes de estudiar servicio por servicio, estos conceptos son la base de casi todas las preguntas del examen. Si algo aquí no te sale de memoria, repásalo primero.
¿Qué es el Well-Architected Framework y por qué existe?

Piensa en el Well-Architected Framework como una lista para revisar si una "casa" tecnológica está bien construida. Una aplicación puede funcionar hoy, pero AWS te ayuda a preguntarte: ¿está protegida?, ¿qué ocurre si algo falla?, ¿se vuelve lenta con más usuarios?, ¿estamos pagando de más?, ¿podemos operarla y mejorarla fácilmente?
PilarExplicación simplePregunta que respondeEjemplo
Excelencia Operacional Operar, monitorear y mejorar la aplicación continuamente. "¿Podemos detectar y corregir problemas rápido?" CloudWatch crea una alarma cuando sube el uso de CPU. Infrastructure as Code permite repetir cambios sin errores manuales.
Seguridad Proteger datos, sistemas y accesos. "¿Quién puede entrar y qué puede hacer?" Usar IAM Roles en vez de credenciales guardadas en código. Cifrar datos con KMS.
Confiabilidad La aplicación resiste fallas y se recupera. "¿Seguirá funcionando si falla un servidor o una zona?" Ejecutar instancias en varias Availability Zones con Auto Scaling y Load Balancer.
Eficiencia de Rendimiento Usar recursos adecuados para responder rápido y escalar. "¿Mantendrá buen rendimiento cuando aumente la demanda?" Usar CloudFront para entregar contenido cerca del usuario, o ElastiCache para reducir lecturas a la base de datos.
Optimización de Costos Entregar lo necesario sin pagar por recursos desperdiciados. "¿Hay una forma más económica de cumplir el mismo requisito?" Usar S3 Lifecycle para mover archivos poco usados a una clase más barata.
Sostenibilidad Reducir el consumo de recursos y el impacto ambiental. "¿Podemos entregar el resultado usando menos recursos?" Apagar recursos sin uso, usar serverless para cargas intermitentes y dimensionar correctamente las instancias.
Para el examen no necesitas memorizar definiciones largas. Aprende a detectar la intención detrás de cada frase:
  • "Monitorear, automatizar despliegues, responder incidentes" → Excelencia Operacional
  • "Permisos, cifrado, MFA, secretos, accesos" → Seguridad
  • "Failover, Multi-AZ, backups, recuperación ante desastres" → Confiabilidad
  • "Latencia, caché, escalabilidad, throughput" → Eficiencia de Rendimiento
  • "Más económico, eliminar desperdicio, right-sizing" → Optimización de Costos
  • "Reducir consumo, apagar recursos, uso energético" → Sostenibilidad

La clave: una decisión puede apoyar varios pilares a la vez, pero el enunciado normalmente destaca una prioridad. Por ejemplo, mover datos de S3 Standard a Glacier busca principalmente Optimización de Costos; desplegar la aplicación en dos Availability Zones busca principalmente Confiabilidad.

1. Diseño de Arquitecturas Seguras 30% del examen
Es el dominio con más peso individual. Enfócate en IAM (siempre aparece), cifrado con KMS y en distinguir bien Security Groups de NACLs y User Pools de Identity Pools: son las confusiones más comunes.

Identidad y acceso

ServicioQué esPrioridadDebes memorizarTip / Comparación clave
AWS IAM Control de acceso a recursos AWS mediante usuarios, grupos, roles y políticas. Alta Orden de evaluación: Explicit Deny > Explicit Allow > Implicit Deny. Los roles son identidades temporales asumibles, distintas de los usuarios. Nunca hardcodear credenciales: siempre usar Roles para servicios AWS. Si la pregunta menciona "acceso temporal", "sin almacenar credenciales" o "servicio a servicio" → IAM Role.
Amazon Cognito Autenticación, autorización y gestión de usuarios para apps web/móviles. Alta User Pools: autenticación (directorio de usuarios, sign-up/sign-in, MFA). Identity Pools: autorización (credenciales temporales de AWS vía STS para acceder a recursos como S3/DynamoDB directamente desde el cliente). "Login social (Google/Facebook) con acceso directo a S3 desde el móvil" → Identity Pools. "Sign-up/sign-in propio de la app" → User Pools.
AWS Directory Service Integra Microsoft Active Directory con servicios AWS. Baja AWS Managed Microsoft AD soporta trust relationships con AD on-premises. AD Connector es solo un proxy/redirector (requiere VPN o Direct Connect). No soporta MFA nativo ni LDAPS. "Extender AD on-premises a AWS" o "SSO con Office 365" → Directory Service.
AWS RAM Resource Access Manager: comparte recursos AWS entre cuentas o dentro de una Organization. Baja Evita duplicar recursos (ej. subnets, Transit Gateway) entre cuentas. No cobra por compartir, solo por el recurso. "Compartir un recurso entre cuentas sin duplicarlo" → RAM.

Cifrado y gestión de secretos

ServicioQué esPrioridadDebes memorizarTip / Comparación clave
AWS KMS Servicio para crear y gestionar claves de cifrado (CMKs), integrado con S3, EBS y RDS. Alta Rotación automática anual de claves gestionadas por el cliente. Envelope encryption: cifra el dato con una data key y esta se cifra con la master key. Claves regionales salvo Multi-Region Keys. KMS es cifrado gestionado multi-tenant. Si piden hardware dedicado con FIPS 140-2 nivel 3 → CloudHSM (no KMS).
AWS Secrets Manager Almacena, rota y recupera credenciales sensibles (passwords, API keys, tokens). Media Rotación automática nativa para RDS/Aurora/Redshift/DocumentDB. Se integra con KMS para cifrado en reposo. Secrets Manager ofrece rotación automática pero es más caro. Parameter Store (dentro de Systems Manager) es gratis en su nivel estándar, sin rotación nativa. "Rotación automática de contraseñas de base de datos" → Secrets Manager.
AWS Certificate Manager (ACM) Provisiona, gestiona y renueva certificados SSL/TLS. Media Los certificados públicos de ACM son gratis cuando se usan con servicios integrados (ELB, CloudFront, API Gateway). ACM Private CA sí tiene costo, para PKI interno. "HTTPS gratis en un ALB o CloudFront" → ACM.

Detección de amenazas y compliance

ServicioQué esPrioridadDebes memorizarTip / Comparación clave
Amazon GuardDuty Detección inteligente de amenazas mediante ML, analizando CloudTrail, VPC Flow Logs y DNS logs. Alta No requiere agentes. Detección continua y de bajo impacto. Genera findings con nivel de severidad. "Detectar actividad anómala o comportamiento malicioso automáticamente" → GuardDuty.
Amazon Inspector Escaneo automatizado de vulnerabilidades en EC2, imágenes ECR y funciones Lambda. Media Usa la base de datos CVE. Evalúa exposición de red además de vulnerabilidades de software. "Escanear vulnerabilidades conocidas (CVE) en mis instancias" → Inspector.
Amazon Macie Detección de datos sensibles (PII) en S3 usando ML. Media Se enfoca específicamente en S3. Genera alertas de exposición de datos sensibles. "Encontrar información personal identificable (PII) en mis buckets" → Macie.
AWS Security Hub Vista centralizada de alertas de seguridad y estado de cumplimiento (agrega GuardDuty, Inspector, Macie e IAM Access Analyzer). Media Verificaciones automáticas contra PCI DSS y CIS AWS Foundations Benchmark. Requiere habilitarse por región. "Panel único de seguridad multi-servicio" → Security Hub (no confundir con GuardDuty, que solo detecta amenazas).

Seguridad de red (VPC)

ServicioQué esPrioridadDebes memorizarTip / Comparación clave
Security Groups Firewall virtual a nivel de instancia/ENI. Alta Stateful: el tráfico de retorno se permite automáticamente. Solo permite reglas allow, no puede denegar explícitamente. Por defecto todo el tráfico saliente está permitido y el entrante denegado. Clásico: SG a nivel de instancia y stateful; NACL a nivel de subred y stateless. Es de las comparaciones más preguntadas del examen.
Network ACLs (NACLs) Firewall a nivel de subred. Alta Stateless: hay que definir reglas de entrada y salida explícitamente. Permite reglas allow y deny. Se evalúan en orden numérico de regla. Una NACL custom deniega todo por defecto; la NACL default permite todo por defecto (al revés que los Security Groups custom).

2. Diseño de Arquitecturas Resilientes 26% del examen
Aquí se prueba tu criterio de alta disponibilidad y desacoplamiento. La confusión más común es Multi-AZ contra Read Replicas, y también SQS contra SNS. Domínalas y tienes gran parte del dominio resuelto.

Alta disponibilidad de cómputo

ServicioQué esPrioridadDebes memorizarTip / Comparación clave
EC2 Auto Scaling Ajusta automáticamente la cantidad de instancias EC2 según demanda o calendario. Alta Tipos de política: Target Tracking (mantener métrica objetivo), Step Scaling, Scheduled, Predictive (ML). Lifecycle Hooks pausan la instancia para ejecutar acciones custom antes de entrar o salir de servicio. Casi siempre es parte de la respuesta correcta cuando la pregunta pide alta disponibilidad más elasticidad.
Elastic Load Balancing (ELB) Distribuye tráfico entrante entre múltiples targets a través de AZs. Alta Ver comparación ALB/NLB/GWLB en el Dominio 3 (ahí pesa más por rendimiento), pero recuerda: siempre multi-AZ, con health checks que sacan targets no saludables automáticamente. ELB junto con Auto Scaling Group es el combo estándar de alta disponibilidad.
AWS Elastic Beanstalk PaaS que despliega y escala apps web automáticamente, con EC2, ELB y Auto Scaling gestionados por AWS. Media Tú controlas el código, AWS controla la infraestructura subyacente. Estrategias de despliegue: All at once, Rolling, Rolling with batch, Immutable, Blue/Green. Es gratis, solo pagas los recursos. "Desplegar rápido sin experiencia DevOps pero con acceso a los recursos subyacentes" → Elastic Beanstalk.
AWS Outposts Hardware físico de AWS instalado en tu datacenter on-premises. Baja Mismas APIs y servicios AWS localmente. Se usa para baja latencia crítica o residencia de datos. "Necesito servicios AWS pero los datos no pueden salir de mi datacenter" → Outposts.
AWS Wavelength Cómputo y storage en el edge de redes 5G. Baja Latencia ultra baja, menor a 10 ms, para dispositivos 5G. "Gaming móvil o AR/VR con latencia ultra baja sobre 5G" → Wavelength.

Bases de datos resilientes

ServicioQué esPrioridadDebes memorizarTip / Comparación clave
RDS Multi-AZ Réplica sincrónica en otra AZ con failover automático. Alta Mantiene el mismo endpoint tras el failover, ya que el DNS se actualiza automáticamente. El objetivo es alta disponibilidad, no performance. La confusión número uno del examen: Multi-AZ es HA (replicación síncrona, failover automático) mientras que Read Replicas es performance de lectura (replicación asíncrona, promoción manual, endpoint distinto).
RDS Read Replicas Réplicas de solo lectura para escalar lecturas. Alta Hasta 5 en RDS estándar y hasta 15 en Aurora. La replicación es asíncrona, por lo que puede haber lag. Pueden ubicarse cross-region. Si la pregunta pide "reducir carga de lectura en la base de datos" → Read Replicas. Si pide "que sobreviva a la caída de una AZ" → Multi-AZ.
Amazon Aurora Motor relacional compatible con MySQL/PostgreSQL, 5 veces más rápido que MySQL y 3 veces más rápido que PostgreSQL. Alta 6 copias de datos en 3 AZs automáticamente. Hasta 15 read replicas con lag menor a 100 ms (contra 5 en RDS). Aurora Global Database replica cross-region en menos de 1 segundo para DR. Backtrack permite viajar en el tiempo sin un restore completo. Cuando la pregunta pide máxima resiliencia junto con performance en relacional, casi siempre la respuesta es Aurora sobre RDS estándar.
DynamoDB Global Tables Replicación activa-activa multi-región de tablas DynamoDB. Media Replicación en milisegundos; todas las regiones aceptan lectura y escritura. "NoSQL con recuperación ante desastre multi-región activo-activo" → Global Tables.
DynamoDB Streams Captura cambios de items en tiempo real, con retención de 24 horas. Media Se consume vía Lambda o Kinesis Client Library. Habilita arquitecturas event-driven sobre cambios de datos. "Reaccionar en tiempo real a cambios en una tabla DynamoDB" → DynamoDB Streams con Lambda.

Almacenamiento resiliente y desacoplamiento

ServicioQué esPrioridadDebes memorizarTip / Comparación clave
Amazon S3 Almacenamiento de objetos con durabilidad de 99.999999999% (11 nueves). Alta Replicado automáticamente entre 3 o más AZs, salvo la clase One Zone-IA. El versionado protege contra borrado accidental. Existe replicación cross-region (CRR) y same-region (SRR). Ver clases de almacenamiento en el Dominio 4, donde pesan más por costo.
Amazon EFS Sistema de archivos NFS compartido, con replicación multi-AZ automática. Media Accesible simultáneamente desde miles de instancias EC2 en distintas AZs. Solo funciona en Linux. "Sistema de archivos compartido entre múltiples instancias en distintas AZs" → EFS (no EBS, que está limitado a una sola AZ).
AWS Backup Automatiza y centraliza backups de recursos AWS como EC2, RDS, EFS y DynamoDB. Media Las políticas se basan en tags. Soporta backup cross-account y cross-region para DR. "Centralizar y automatizar backups de múltiples servicios con una sola política" → AWS Backup.
Amazon SQS Colas de mensajes para desacoplamiento asíncrono. Alta Standard: throughput ilimitado, orden best-effort, entrega al menos una vez. FIFO: orden estricto, exactly-once, hasta 3000 msg/s con batching. Dead Letter Queue (DLQ) para mensajes fallidos. El visibility timeout evita procesamiento duplicado. "Desacoplar productor y consumidor de forma asíncrona" → SQS es casi siempre la primera opción a considerar.
Amazon SNS Servicio pub/sub para notificaciones y fan-out a múltiples suscriptores. Alta Un mensaje llega a múltiples destinos: email, SMS, Lambda, SQS, HTTP. El message filtering permite que cada suscriptor reciba solo lo relevante. Patrón muy preguntado: SNS con SQS (fan-out): un publisher y múltiples colas SQS, cada una con su propio consumidor, para que cada sistema procese a su ritmo sin perder mensajes.
Amazon EventBridge Bus de eventos serverless con enrutamiento basado en reglas. Media Es la evolución de CloudWatch Events. Ofrece más de 100 integraciones con AWS y partners SaaS. Soporta event replay y schema registry. Úsalo cuando necesites routing de eventos complejo, con múltiples reglas, orígenes y destinos, algo más avanzado que un simple SNS/SQS.
AWS Step Functions Orquestación visual de flujos de trabajo serverless mediante state machines. Media Standard: hasta 1 año de duración, exactly-once. Express: menos de 5 minutos, at-least-once, más barato. Los reintentos y el manejo de errores están integrados. "Orquestar múltiples pasos o microservicios con lógica de reintentos y ramificación" → Step Functions.
Estrategias de Disaster Recovery, de menor a mayor costo: Backup and Restore (RTO/RPO altos, muy barato) → Pilot Light (recursos mínimos siempre activos) → Warm Standby (versión reducida siempre corriendo) → Multi-Site Active-Active (todas las regiones sirviendo tráfico, RTO/RPO casi cero, el más caro).

3. Diseño de Arquitecturas de Alto Rendimiento 24% del examen
Aquí se evalúa que sepas elegir el servicio o tipo correcto según el patrón de acceso o de carga. Domina bien los tipos de EBS, los tipos de ELB y cuándo usar caché con CloudFront, ElastiCache o DAX.

Cómputo

ServicioQué esPrioridadDebes memorizarTip / Comparación clave
Amazon EC2 (familias) Máquinas virtuales en la nube. Alta General Purpose (T, M): balance. Compute Optimized (C): CPU intensivo. Memory Optimized (R, X, z): bases de datos en memoria. Storage Optimized (I, D, H): I/O intensivo. Accelerated (P, G, F): GPU/ML. Si la pregunta describe la carga, por ejemplo "procesamiento intensivo de CPU", la familia correcta suele ser la respuesta directa.
EC2 Placement Groups Estrategias de ubicación física de instancias. Media Cluster: baja latencia entre instancias, ideal para HPC. Spread: máxima disponibilidad, instancias en hardware distinto. Partition: apps distribuidas como Hadoop o Kafka. "Latencia de red mínima entre instancias" → Cluster Placement Group.
AWS Lambda Cómputo serverless activado por eventos. Alta Timeout máximo de 15 minutos. Memoria de 128 MB a 10 GB, con la CPU escalando proporcionalmente. Cold starts en la primera invocación. Concurrencia default de 1000, ajustable. Layers para código compartido, máximo 5. "Event-driven, menos de 15 minutos, sin gestionar servidores" → Lambda es casi siempre la respuesta serverless por defecto.
AWS Fargate Cómputo serverless para contenedores, usado con ECS o EKS. Media Sin gestión de instancias EC2. Pago por vCPU y memoria usada. Cada tarea tiene kernel, memoria y ENI dedicados para aislamiento. Fargate es serverless pero más caro; el launch type EC2 da control total y ahorro con Spot.
Amazon ECS Orquestador de contenedores nativo de AWS. Media Las Task Definitions son el blueprint del contenedor y los Services mantienen N tasks corriendo, con integración nativa con ALB, IAM y CloudWatch. Es más simple que EKS; ideal si no necesitas el ecosistema estándar de Kubernetes.
Amazon EKS Kubernetes completamente gestionado. Media El control plane está administrado en alta disponibilidad multi-AZ, y es compatible con Kubernetes estándar (CNCF). "Necesito Kubernetes estándar o portabilidad multi-cloud" → EKS por sobre ECS.
Amazon ECR Registro privado de imágenes de contenedor. Baja Integrado con IAM, cifrado con KMS y con escaneo de vulnerabilidades integrado. Es el equivalente privado y seguro de Docker Hub, integrado nativamente con ECS, EKS y Lambda.
AWS Batch Ejecuta miles de trabajos batch sin gestionar infraestructura. Baja Corre sobre EC2, incluyendo Spot, o sobre Fargate. Gestiona Job Queues, Job Definitions y Compute Environments. "Procesamiento masivo por lotes, tolerante a fallos, con dependencias entre jobs" → AWS Batch.

Almacenamiento de alto rendimiento

ServicioQué esPrioridadDebes memorizarTip / Comparación clave
EBS gp2/gp3 SSD de propósito general. Alta Entre 3000 y 16000 IOPS. Ideal para boot volumes, dev/test y apps de latencia baja o media. Es la opción por defecto cuando no se especifica una necesidad extrema de IOPS.
EBS io1/io2 SSD Provisioned IOPS. Alta Hasta 64000 IOPS, consistentes. Soporta Multi-Attach (varias instancias sobre el mismo volumen). Ideal para bases de datos transaccionales críticas. "IOPS altos y consistentes para una base de datos crítica" → io1/io2.
EBS st1 / sc1 HDD throughput-optimized (st1) y cold (sc1). Media st1 sirve para big data, data warehouse y streaming, por su throughput secuencial. sc1 es para datos fríos, de menor costo y no apto para boot. "Bajo costo, acceso poco frecuente, sin necesidad de IOPS" → sc1.
EBS contra Instance Store Comparación de almacenamiento de bloques. Media Instance Store es efímero: se pierde al detener o crashear la instancia, no soporta snapshots, pero ofrece mayor IOPS. EBS es persistente, soporta snapshots y se puede desconectar/reconectar entre instancias. "Datos que deben persistir tras detener la instancia" → EBS, nunca Instance Store.
EFS: modos de performance y throughput Configuraciones de rendimiento de EFS. Baja Performance: General Purpose (baja latencia) contra Max I/O (alto throughput, mayor latencia). Throughput: Bursting (default), Provisioned y Elastic. Si hay miles de conexiones concurrentes con más tolerancia a latencia → Max I/O.
Amazon FSx for Windows Sistema de archivos SMB gestionado para cargas Windows. Baja Integración nativa con Active Directory. Despliegue multi-AZ con failover automático. "Compartir archivos con protocolo SMB para apps Windows" → FSx for Windows.
Amazon FSx for Lustre Sistema de archivos paralelo de altísimo rendimiento, orientado a HPC. Baja Latencias sub-milisegundo y millones de IOPS. Integración directa con S3, procesando objetos como archivos. "HPC, machine learning a gran escala o procesamiento masivo paralelo" → FSx for Lustre.
FSx for NetApp ONTAP y OpenZFS Sistemas de archivos gestionados compatibles con NetApp y con ZFS. Baja ONTAP soporta multi-protocolo (NFS, SMB, iSCSI). OpenZFS está pensado para migración desde ZFS on-premises. Aparecen poco en el examen; basta con reconocer el nombre y su propósito general.
S3 Transfer Acceleration Acelera subidas y bajadas usando la red edge de CloudFront. Media Es útil cuando los usuarios están geográficamente lejos de la región del bucket. "Subir archivos grandes rápido desde ubicaciones remotas" → S3 Transfer Acceleration.

Bases de datos y caché de alto rendimiento

ServicioQué esPrioridadDebes memorizarTip / Comparación clave
Amazon DynamoDB Base de datos NoSQL serverless, con latencia de milisegundos de un dígito. Alta Partition Key o Partition Key más Sort Key. GSI (índice con distinta partition/sort key) contra LSI (misma partition key, distinta sort key, se define al crear la tabla). Capacidad on-demand contra provisioned. "NoSQL serverless con escalado ilimitado y latencia de milisegundos" → DynamoDB.
DynamoDB Accelerator (DAX) Caché en memoria administrada específica para DynamoDB. Media Reduce la latencia de milisegundos a microsegundos. Es solo para DynamoDB, no confundir con ElastiCache. "Reducir al máximo la latencia de lecturas de DynamoDB" → DAX.
Amazon ElastiCache Caché en memoria administrado, con motores Redis o Memcached. Alta Redis ofrece persistencia, replicación multi-AZ, estructuras complejas y pub/sub. Memcached es simple, multi-threaded, sin persistencia ni replicación, solo con sharding horizontal. Sesiones de usuario que necesitan alta disponibilidad → Redis. Cache simple de queries en multi-core → Memcached.
Amazon Aurora (rendimiento) Ver también el Dominio 2 para su rol en resiliencia. Alta Aurora Replicas tienen lag menor a 10 ms para escalar lectura. Parallel Query acelera analítica sobre datos transaccionales. Cloning rápido, tipo copy-on-write, sirve para entornos de prueba. Es superior a RDS estándar en casi cualquier escenario de performance, salvo cuando el costo es la prioridad principal.
Amazon Redshift Data warehouse columnar para OLAP a escala de petabytes. Media Usa MPP (Massively Parallel Processing). Redshift Spectrum permite consultar S3 sin cargar los datos. La compresión columnar llega a ser de aproximadamente 10 veces. RDS y Aurora son para OLTP transaccional. Redshift es para OLAP analítico, con queries complejas sobre grandes volúmenes.

Streaming e ingestión en tiempo real

ServicioQué esPrioridadDebes memorizarTip / Comparación clave
Kinesis Data Streams Streaming de datos en tiempo real con control total. Media Shards escalables manualmente. Retención configurable de 1 a 365 días. Consumidores personalizados vía KCL. Si necesitas procesamiento custom y reproceso de eventos → Data Streams.
Kinesis Data Firehose Carga automática de streaming hacia S3, Redshift, OpenSearch o Splunk. Media Es completamente gestionado, casi en tiempo real, con un buffer de aproximadamente 60 segundos. No requiere gestión de shards. Si solo necesitas ingerir y entregar sin procesamiento custom → Firehose (más simple que Data Streams).
Kinesis Video Streams Ingesta y almacenamiento de streams de video para análisis con ML. Baja Se integra con Rekognition Video. Cualquier escenario que mencione "streaming de video para análisis" → Kinesis Video Streams.
Amazon MSK Apache Kafka completamente administrado. Baja Úsalo cuando ya existe un ecosistema Kafka, por su compatibilidad de API nativa, no como reemplazo genérico de Kinesis. "Migrar un Kafka on-premises existente a AWS" → MSK. Para una app nueva sin atadura a Kafka, Kinesis suele ser más simple.

Redes de alto rendimiento

ServicioQué esPrioridadDebes memorizarTip / Comparación clave
Application Load Balancer (ALB) ELB de Capa 7, para HTTP/HTTPS. Alta Routing por path, host, headers o query string. Los targets pueden ser EC2, IP o Lambda. Soporta WebSocket. Cualquier escenario web HTTP/HTTPS con routing avanzado → ALB.
Network Load Balancer (NLB) ELB de Capa 4, para TCP/UDP, de ultra performance. Alta Soporta millones de solicitudes por segundo. Ofrece IP estática por AZ y preserva la IP de origen del cliente. "Necesito una IP estática" o "gaming/IoT de altísimo throughput" → NLB.
Gateway Load Balancer (GWLB) ELB de Capa 3, para appliances de terceros. Baja Está diseñado para insertar firewalls, IDS o IPS de terceros de forma transparente en el flujo de tráfico. "Insertar un appliance de seguridad de un partner en la ruta del tráfico" → GWLB.
Amazon CloudFront CDN global con más de 450 edge locations. Alta Cachea contenido estático y dinámico. Signed URLs y Signed Cookies para contenido privado. Lambda@Edge para lógica en el edge. Origin failover para alta disponibilidad. Reduce la latencia global y descarga el origen. Ver comparación con Global Accelerator más abajo.
AWS Global Accelerator Dos IPs Anycast estáticas que enrutan por la red privada de AWS. Media No cachea: es un proxy inteligente, no una CDN. El failover ocurre en menos de 30 segundos. Es útil para apps no HTTP, como TCP o UDP. "Necesito IPs estáticas globales" o "mejorar rendimiento de protocolos no HTTP" → Global Accelerator.
Amazon API Gateway Crea, publica y gestiona APIs REST, HTTP y WebSocket. Alta REST API: completa, con caching y transformación. HTTP API: más simple, más barata y de menor latencia. WebSocket API: comunicación bidireccional. Es la puerta de entrada estándar para arquitecturas serverless con Lambda detrás.
AWS Direct Connect Conexión de red dedicada entre on-premises y AWS. Media Ofrece 1, 10 o 100 Gbps. No está cifrado por defecto, se puede usar VPN sobre DX si se requiere. El setup toma semanas. "Conexión consistente y de alto ancho de banda" → Direct Connect. Si se necesita un setup rápido → Site-to-Site VPN.
AWS Transit Gateway Hub central para interconectar VPCs y redes on-premises. Media Usa arquitectura hub-and-spoke, simplificando topologías de malla compleja de VPC Peering. Soporta multicast. "Conectar decenas o cientos de VPCs sin una malla de peerings" → Transit Gateway.
AWS PrivateLink Conectividad privada entre VPCs y servicios AWS, sin pasar por internet público. Media Interface Endpoints: ENI con IP privada, para la mayoría de servicios. Gateway Endpoints: solo para S3 y DynamoDB, vía route table, sin costo por hora. "Acceder a S3/DynamoDB desde una subred privada sin salir a internet ni usar NAT" → Gateway Endpoint (más barato que Interface Endpoint).
Amazon VPC (componentes) Red virtual aislada. Alta Una subnet pública tiene ruta a un Internet Gateway; una subnet privada usa un NAT Gateway para su salida. El NAT Gateway está gestionado y es escalable; la NAT Instance es manual y ya se considera legado. Es el fundamento de casi cualquier diagrama de arquitectura del examen; repásalo hasta que sea automático.
Route 53 (routing por latencia y geo) Ver también el Dominio 2 para failover. Alta Latency-based: enruta al endpoint de menor latencia. Geolocation: por ubicación del usuario, útil para cumplimiento normativo. Geoproximity: por proximidad con bias ajustable. Weighted: distribución porcentual, ideal para blue/green. Memoriza qué política corresponde a cada palabra clave del enunciado (ver la sección de Palabras Gatillo).

4. Diseño de Arquitecturas Optimizadas en Costos 20% del examen
Es el dominio más "matemático": se trata de reconocer el modelo de precio correcto según el patrón de uso, ya sea predecible, interrumpible o variable. Memoriza bien las clases de S3 y los modelos de compra de EC2.

Modelos de precio de cómputo

ServicioQué esPrioridadDebes memorizarTip / Comparación clave
EC2 On-Demand Pago por segundo, sin compromiso. Alta Ofrece máxima flexibilidad, con el mayor costo por hora. Es ideal para cargas nuevas o impredecibles a corto plazo. Es el punto de partida de comparación para todos los demás modelos.
EC2 Reserved Instances (RI) Compromiso de 1 o 3 años, con hasta 75% de descuento. Alta Las Standard están atadas a familia de instancia y región; las Convertible ofrecen algo de flexibilidad. "Carga predecible y estable a largo plazo" → RI o Savings Plans, según cuánta flexibilidad se requiera.
EC2 Spot Instances Hasta 90% de descuento, interrumpible con 2 minutos de aviso. Alta Es ideal para cargas fault-tolerant: batch, rendering, big data, CI/CD. "Menor costo posible" junto con "tolera interrupciones" → Spot es casi siempre la respuesta.
Dedicated Hosts y Dedicated Instances Hardware físico dedicado o aislado. Baja Es la opción más cara. Se usa por requisitos de licenciamiento (BYOL) o compliance estricto, no para optimizar costo. Si la pregunta menciona "licencias existentes por socket o core" → Dedicated Host.
Savings Plans (Compute contra EC2 Instance) Descuento por compromiso de uso, de 1 a 3 años, medido en dólares por hora. Alta Compute Savings Plans: hasta 66% de descuento, aplica a EC2, Fargate y Lambda en cualquier región, familia u OS (máxima flexibilidad). EC2 Instance Savings Plans: hasta 72%, pero atado a una familia de instancia y región específica. "Compromiso estable pero necesito flexibilidad entre EC2, Fargate y Lambda" → Compute Savings Plans.

Almacenamiento optimizado en costo

ServicioQué esPrioridadDebes memorizarTip / Comparación clave
S3 Standard Acceso frecuente, para uso general. Alta Ofrece 99.99% de disponibilidad, sin mínimo de días de almacenamiento. Es el punto de partida; se optimiza moviendo datos a otras clases según antigüedad o frecuencia de acceso.
S3 Standard-IA y One Zone-IA Clases para acceso infrecuente. Alta Requieren un mínimo de 30 días de almacenamiento. One Zone-IA vive en una sola AZ, es más barato pero menos duradero ante la pérdida de una AZ, y solo sirve para datos recreables. "Datos accedidos pocas veces al mes pero críticos" → Standard-IA. "Datos no críticos y recreables" → One Zone-IA.
S3 Intelligent-Tiering Mueve automáticamente los datos entre tiers según su patrón de acceso. Media Es ideal cuando no conoces el patrón de acceso de los datos. "No sé cómo se van a acceder los datos a futuro" → Intelligent-Tiering.
S3 Glacier Instant y Flexible Retrieval Clases para archivado de largo plazo. Alta Instant Retrieval responde en milisegundos. Flexible Retrieval responde en minutos u horas: Expedited de 1 a 5 minutos, Standard de 3 a 5 horas y Bulk de 5 a 12 horas. "Archivo que rara vez se consulta pero a veces se necesita rápido" → Glacier Instant Retrieval.
S3 Glacier Deep Archive La clase de almacenamiento más barata de todas. Alta El retrieval toma horas, incluso más de 12. Requiere un mínimo de 180 días de almacenamiento. Está pensado para compliance de varios años. "Retención regulatoria de 7 años o más, casi sin accesos" → Glacier Deep Archive.
S3 Lifecycle Policies Automatiza la transición entre clases de almacenamiento. Alta Un ejemplo típico: Standard entre 0 y 30 días, Standard-IA entre 30 y 90 días, Glacier a partir de 90 días y Deep Archive a partir de 180 días. Se configuran a nivel de bucket o de prefix. Cualquier pregunta sobre optimizar el costo de almacenamiento a largo plazo de forma automática → Lifecycle Policy.

AWS Control Tower Extiende Organizations con un Landing Zone de mejores prácticas. AWS Health Dashboard Eventos de servicio en tiempo real y notificaciones de cuenta. Baja Se integra con EventBridge para automatizar respuestas a eventos de AWS que afectan tus recursos. "Recibir alertas proactivas sobre incidentes de AWS que afectan mis recursos" → AWS Health Dashboard.

12. Comparaciones críticas (memorizar sí o sí)
Estas son las comparaciones que más se repiten en preguntas del examen real, según los patrones de tus guías. Si te sabes esta sección de memoria, resuelves gran parte de las preguntas "trampa".
ComparaciónDiferencia clave
RDS Multi-AZ contra Read ReplicasMulti-AZ es alta disponibilidad: síncrono, failover automático, mismo endpoint. Read Replicas es performance de lectura: asíncrono, promoción manual, endpoint distinto.
RDS, DynamoDB, Redshift y AuroraRDS y Aurora son OLTP relacional. DynamoDB es NoSQL key-value serverless. Redshift es OLAP, un data warehouse a escala de petabytes.
S3, EBS, EFS y FSxS3 es almacenamiento de objetos, ilimitado y global. EBS es de bloques, en una sola AZ, atado a una instancia. EFS es de archivos NFS compartidos multi-AZ, solo Linux. FSx son sistemas de archivos gestionados especializados, como Windows o Lustre.
ALB, NLB y GWLBALB es Capa 7, HTTP/HTTPS, con routing avanzado. NLB es Capa 4, TCP/UDP, con IP estática y máximo throughput. GWLB es Capa 3, para appliances de terceros.
CloudFront contra Global AcceleratorCloudFront cachea contenido, funcionando como CDN. Global Accelerator no cachea: es un proxy de red que mejora el enrutamiento y da IPs estáticas, útil para tráfico no HTTP.
Direct Connect contra Site-to-Site VPNDirect Connect es una conexión dedicada, con mayor ancho de banda, sin cifrado nativo y semanas de setup. VPN va sobre internet público, con cifrado IPsec automático y minutos de setup.
Security Groups contra NACLsSG es stateful, a nivel de instancia, solo con reglas allow. NACL es stateless, a nivel de subred, con reglas allow y deny.
KMS, CloudHSM y Secrets ManagerKMS es cifrado gestionado multi-tenant para uso general. CloudHSM es hardware dedicado, FIPS 140-2 nivel 3. Secrets Manager gestiona credenciales con rotación automática.
Cognito User Pools contra Identity PoolsUser Pools es autenticación, un directorio de usuarios. Identity Pools es autorización, con credenciales temporales de AWS.
SNS, SQS y EventBridgeSNS es pub/sub con fan-out inmediato. SQS es una cola de mensajes para desacoplamiento y buffer. EventBridge es enrutamiento de eventos complejo con múltiples reglas y orígenes.
Kinesis Data Streams contra FirehoseData Streams da control total, con shards manuales y reproceso de eventos. Firehose entrega de forma automática y simple a un destino, sin gestión de shards.
EC2, Lambda y FargateEC2 da control total, para cargas de larga duración. Lambda es serverless, event-driven, con un máximo de 15 minutos. Fargate son contenedores serverless, sin gestionar EC2.
On-Demand, Reserved, Spot y Savings PlansOn-Demand es flexible pero caro. RI y Savings Plans convienen para cargas predecibles. Spot es interrumpible y da el máximo ahorro para cargas fault-tolerant.
Route 53: Failover, Weighted, Latency y GeolocationFailover es activo-pasivo con health check. Weighted distribuye por porcentaje, ideal para blue/green. Latency busca la menor latencia posible. Geolocation enruta según la ubicación del usuario, por cumplimiento normativo.

14. Checklist final de repaso
Marca mentalmente, o imprimiendo esta página, lo que ya domines. Lo que quede sin marcar es tu lista de repaso prioritaria antes del examen.

Conceptos fundamentales

  • Los 6 pilares del Well-Architected Framework, de memoria
  • Diferencia entre Region, AZ y Edge Location
  • Modelo de responsabilidad compartida: qué es de AWS y qué es tuyo
  • Cuándo usar cada servicio de cómputo: EC2, Lambda, Fargate, ECS o EKS
  • VPC completo: subnets, route tables, NAT, IGW, endpoints
  • IAM: roles, policies, y la evaluación de permisos donde el deny explícito siempre gana

Servicios clave que debes saber sin dudar

  • EC2: modelos de compra, familias, placement groups
  • S3: clases de almacenamiento, lifecycle, versionado, replicación
  • RDS y Aurora: Multi-AZ contra Read Replica, backups, cifrado
  • DynamoDB: keys, índices GSI y LSI, streams, capacidad
  • Lambda: límites, triggers, cold starts
  • Route 53: las 7 políticas de routing y cuándo usar cada una
  • CloudWatch para monitoreo contra CloudTrail para auditoría, sin confundirlos
  • KMS: cifrado en reposo y en tránsito, envelope encryption

Comparaciones críticas ya dominadas

  • RDS, DynamoDB, Redshift y Aurora
  • S3, EBS, EFS y FSx
  • ALB, NLB y GWLB
  • Direct Connect, VPN y PrivateLink
  • CloudFront contra Global Accelerator
  • SNS, SQS y EventBridge
  • Multi-AZ contra Read Replicas

Estrategia el día del examen

  • 65 preguntas en 130 minutos, aproximadamente 2 minutos por pregunta, y 720 de 1000 puntos para aprobar
  • Identificar la palabra clave del enunciado: menor costo, alta disponibilidad, mínima latencia
  • Eliminar primero las opciones obviamente incorrectas
  • Marcar y continuar en preguntas difíciles, revisando al final
  • Responder todas las preguntas, ya que no hay penalización por respuesta incorrecta
  • Cuidado con preguntas que piden la opción "incorrecta" o "no adecuada"; conviene leerlas dos veces
