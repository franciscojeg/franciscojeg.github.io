0. Fundamentals you should have on autopilot
Before studying service by service, these concepts underpin nearly every question on the exam. If anything here doesn't come to you from memory, review it first.
What is the Well-Architected Framework, and why does it exist?

Think of the Well-Architected Framework as a checklist for whether a technology "house" is well built. An application can work fine today, but AWS pushes you to ask: is it protected? What happens if something fails? Does it slow down as more users show up? Are we overpaying? Can we operate and improve it easily?
PillarSimple explanationQuestion it answersExample
Operational Excellence Operate, monitor and continuously improve the application. "Can we detect and fix problems fast?" CloudWatch fires an alarm when CPU usage climbs. Infrastructure as Code lets you repeat changes without manual errors.
Security Protect data, systems and access. "Who can get in, and what can they do?" Use IAM Roles instead of credentials stored in code. Encrypt data with KMS.
Reliability The application withstands failures and recovers. "Will it keep working if a server or a zone goes down?" Run instances across multiple Availability Zones with Auto Scaling and a Load Balancer.
Performance Efficiency Use the right resources to respond fast and scale. "Will it keep good performance as demand grows?" Use CloudFront to deliver content close to the user, or ElastiCache to cut down on database reads.
Cost Optimization Deliver what's needed without paying for wasted resources. "Is there a cheaper way to meet the same requirement?" Use S3 Lifecycle to move rarely-used files to a cheaper storage class.
Sustainability Reduce resource consumption and environmental impact. "Can we deliver the same result using fewer resources?" Turn off unused resources, use serverless for intermittent workloads, and right-size instances.
For the exam you don't need to memorize long definitions. Learn to spot the intent behind each phrase:
  • "Monitor, automate deployments, respond to incidents" → Operational Excellence
  • "Permissions, encryption, MFA, secrets, access" → Security
  • "Failover, Multi-AZ, backups, disaster recovery" → Reliability
  • "Latency, caching, scalability, throughput" → Performance Efficiency
  • "Cheaper, eliminate waste, right-sizing" → Cost Optimization
  • "Reduce consumption, shut down resources, energy usage" → Sustainability

The key: a decision can support several pillars at once, but the question usually highlights one priority. For example, moving data from S3 Standard to Glacier is mainly Cost Optimization; deploying the application across two Availability Zones is mainly Reliability.

1. Designing Secure Architectures 30% of the exam
This is the single heaviest-weighted domain. Focus on IAM (it always shows up), encryption with KMS, and clearly telling apart Security Groups from NACLs and User Pools from Identity Pools: these are the most common mix-ups.

Identity and access

ServiceWhat it isPriorityMust memorizeKey tip / comparison
AWS IAM Access control for AWS resources via users, groups, roles and policies. High Evaluation order: Explicit Deny > Explicit Allow > Implicit Deny. Roles are temporary, assumable identities, distinct from users. Never hardcode credentials: always use Roles for AWS services. If the question mentions "temporary access," "without storing credentials," or "service to service" → IAM Role.
Amazon Cognito Authentication, authorization and user management for web/mobile apps. High User Pools: authentication (user directory, sign-up/sign-in, MFA). Identity Pools: authorization (temporary AWS credentials via STS to access resources like S3/DynamoDB directly from the client). "Social login (Google/Facebook) with direct S3 access from mobile" → Identity Pools. "The app's own sign-up/sign-in" → User Pools.
AWS Directory Service Integrates Microsoft Active Directory with AWS services. Low AWS Managed Microsoft AD supports trust relationships with on-premises AD. AD Connector is just a proxy/redirector (requires VPN or Direct Connect). Doesn't support native MFA or LDAPS. "Extend on-premises AD to AWS" or "SSO with Office 365" → Directory Service.
AWS RAM Resource Access Manager: shares AWS resources across accounts or within an Organization. Low Avoids duplicating resources (e.g. subnets, Transit Gateway) across accounts. There's no charge for sharing, only for the resource itself. "Share a resource across accounts without duplicating it" → RAM.

Encryption and secrets management

ServiceWhat it isPriorityMust memorizeKey tip / comparison
AWS KMS Service for creating and managing encryption keys (CMKs), integrated with S3, EBS and RDS. High Automatic annual rotation for customer-managed keys. Envelope encryption: the data is encrypted with a data key, and that data key is itself encrypted with the master key. Keys are regional unless they're Multi-Region Keys. KMS is multi-tenant managed encryption. If dedicated hardware with FIPS 140-2 level 3 is required → CloudHSM (not KMS).
AWS Secrets Manager Stores, rotates and retrieves sensitive credentials (passwords, API keys, tokens). Medium Native automatic rotation for RDS/Aurora/Redshift/DocumentDB. Integrates with KMS for encryption at rest. Secrets Manager offers automatic rotation but costs more. Parameter Store (inside Systems Manager) is free at its standard tier, with no native rotation. "Automatic rotation of database passwords" → Secrets Manager.
AWS Certificate Manager (ACM) Provisions, manages and renews SSL/TLS certificates. Medium ACM's public certificates are free when used with integrated services (ELB, CloudFront, API Gateway). ACM Private CA does have a cost, for internal PKI. "Free HTTPS on an ALB or CloudFront" → ACM.

Threat detection and compliance

ServiceWhat it isPriorityMust memorizeKey tip / comparison
Amazon GuardDuty Intelligent threat detection using ML, analyzing CloudTrail, VPC Flow Logs and DNS logs. High Requires no agents. Continuous, low-impact detection. Generates findings with a severity level. "Automatically detect anomalous activity or malicious behavior" → GuardDuty.
Amazon Inspector Automated vulnerability scanning for EC2, ECR images and Lambda functions. Medium Uses the CVE database. Also evaluates network exposure, not just software vulnerabilities. "Scan my instances for known vulnerabilities (CVE)" → Inspector.
Amazon Macie Detects sensitive data (PII) in S3 using ML. Medium Focuses specifically on S3. Generates alerts for sensitive data exposure. "Find personally identifiable information (PII) in my buckets" → Macie.
AWS Security Hub Centralized view of security alerts and compliance status (aggregates GuardDuty, Inspector, Macie and IAM Access Analyzer). Medium Automatic checks against PCI DSS and the CIS AWS Foundations Benchmark. Must be enabled per region. "A single multi-service security dashboard" → Security Hub (don't confuse with GuardDuty, which only detects threats).

Network security (VPC)

ServiceWhat it isPriorityMust memorizeKey tip / comparison
Security Groups Virtual firewall at the instance/ENI level. High Stateful: return traffic is automatically allowed. Only allow rules are supported, nothing can be explicitly denied. By default all outbound traffic is allowed and all inbound traffic is denied. Classic: SG is at the instance level and stateful; NACL is at the subnet level and stateless. This is one of the most-tested comparisons on the exam.
Network ACLs (NACLs) Firewall at the subnet level. High Stateless: inbound and outbound rules must be defined explicitly. Supports both allow and deny rules. Evaluated in numeric rule order. A custom NACL denies everything by default; the default NACL allows everything by default (the opposite of custom Security Groups).

2. Designing Resilient Architectures 26% of the exam
This domain tests your judgment on high availability and decoupling. The most common mix-up is Multi-AZ vs Read Replicas, and also SQS vs SNS. Master those and you've solved a large chunk of this domain.

Compute high availability

ServiceWhat it isPriorityMust memorizeKey tip / comparison
EC2 Auto Scaling Automatically adjusts the number of EC2 instances based on demand or a schedule. High Policy types: Target Tracking (keep a target metric), Step Scaling, Scheduled, Predictive (ML-based). Lifecycle Hooks pause an instance to run custom actions before it enters or leaves service. It's almost always part of the correct answer when the question asks for high availability plus elasticity.
Elastic Load Balancing (ELB) Distributes incoming traffic across multiple targets, across AZs. High See the ALB/NLB/GWLB comparison in Domain 3 (it carries more weight there for performance), but remember: always multi-AZ, with health checks that automatically pull unhealthy targets out of rotation. ELB paired with an Auto Scaling Group is the standard high-availability combo.
AWS Elastic Beanstalk PaaS that deploys and scales web apps automatically, with EC2, ELB and Auto Scaling managed by AWS. Medium You control the code, AWS controls the underlying infrastructure. Deployment strategies: All at once, Rolling, Rolling with batch, Immutable, Blue/Green. It's free, you only pay for the underlying resources. "Deploy fast without DevOps expertise but still get access to the underlying resources" → Elastic Beanstalk.
AWS Outposts Physical AWS hardware installed in your on-premises datacenter. Low Same APIs and AWS services running locally. Used for critical low latency or data residency requirements. "I need AWS services but data can't leave my datacenter" → Outposts.
AWS Wavelength Compute and storage at the edge of 5G networks. Low Ultra-low latency, under 10 ms, for 5G devices. "Mobile gaming or AR/VR with ultra-low latency over 5G" → Wavelength.

Resilient databases

ServiceWhat it isPriorityMust memorizeKey tip / comparison
RDS Multi-AZ Synchronous replica in another AZ with automatic failover. High Keeps the same endpoint after failover, since the DNS record updates automatically. The goal is high availability, not performance. The exam's number-one point of confusion: Multi-AZ is HA (synchronous replication, automatic failover) while Read Replicas are read performance (asynchronous replication, manual promotion, a different endpoint).
RDS Read Replicas Read-only replicas to scale reads. High Up to 5 on standard RDS and up to 15 on Aurora. Replication is asynchronous, so there can be lag. They can be placed cross-region. If the question asks to "reduce read load on the database" → Read Replicas. If it asks to "survive the loss of an AZ" → Multi-AZ.
Amazon Aurora Relational engine compatible with MySQL/PostgreSQL, 5x faster than MySQL and 3x faster than PostgreSQL. High Automatically keeps 6 copies of data across 3 AZs. Up to 15 read replicas with under 100 ms lag (vs 5 on RDS). Aurora Global Database replicates cross-region in under 1 second for DR. Backtrack lets you travel back in time without a full restore. When the question asks for maximum resiliency together with relational performance, the answer is almost always Aurora over standard RDS.
DynamoDB Global Tables Multi-region active-active replication for DynamoDB tables. Medium Replication in milliseconds; every region accepts both reads and writes. "NoSQL with active-active multi-region disaster recovery" → Global Tables.
DynamoDB Streams Captures item-level changes in real time, with 24-hour retention. Medium Consumed via Lambda or the Kinesis Client Library. Enables event-driven architectures on top of data changes. "React in real time to changes in a DynamoDB table" → DynamoDB Streams with Lambda.

Resilient storage and decoupling

ServiceWhat it isPriorityMust memorizeKey tip / comparison
Amazon S3 Object storage with 99.999999999% durability (11 nines). High Automatically replicated across 3 or more AZs, except for the One Zone-IA class. Versioning protects against accidental deletion. Both cross-region replication (CRR) and same-region replication (SRR) exist. See the storage classes in Domain 4, where they carry more weight for cost.
Amazon EFS Shared NFS file system, with automatic multi-AZ replication. Medium Accessible simultaneously from thousands of EC2 instances across different AZs. Linux only. "A file system shared across multiple instances in different AZs" → EFS (not EBS, which is limited to a single AZ).
AWS Backup Automates and centralizes backups for AWS resources like EC2, RDS, EFS and DynamoDB. Medium Policies are tag-based. Supports cross-account and cross-region backup for DR. "Centralize and automate backups for multiple services with a single policy" → AWS Backup.
Amazon SQS Message queues for asynchronous decoupling. High Standard: unlimited throughput, best-effort ordering, at-least-once delivery. FIFO: strict ordering, exactly-once, up to 3000 msg/s with batching. Dead Letter Queue (DLQ) for failed messages. The visibility timeout prevents duplicate processing. "Decouple producer and consumer asynchronously" → SQS is almost always the first option to consider.
Amazon SNS Pub/sub service for notifications and fan-out to multiple subscribers. High One message reaches multiple destinations: email, SMS, Lambda, SQS, HTTP. Message filtering lets each subscriber receive only what's relevant to it. A heavily-tested pattern: SNS with SQS (fan-out): one publisher and multiple SQS queues, each with its own consumer, so every system processes at its own pace without losing messages.
Amazon EventBridge Serverless event bus with rule-based routing. Medium It's the evolution of CloudWatch Events. Offers 100+ integrations with AWS and SaaS partners. Supports event replay and a schema registry. Use it when you need complex event routing, with multiple rules, sources and destinations — something more advanced than plain SNS/SQS.
AWS Step Functions Visual orchestration of serverless workflows via state machines. Medium Standard: up to 1 year in duration, exactly-once. Express: under 5 minutes, at-least-once, cheaper. Retries and error handling are built in. "Orchestrate multiple steps or microservices with retry logic and branching" → Step Functions.
Disaster Recovery strategies, from cheapest to most expensive: Backup and Restore (high RTO/RPO, very cheap) → Pilot Light (minimal resources always running) → Warm Standby (a scaled-down version always running) → Multi-Site Active-Active (every region serving traffic, near-zero RTO/RPO, the most expensive).

3. Designing High-Performing Architectures 24% of the exam
This domain tests whether you can pick the right service or type based on the access or workload pattern. Master the EBS types, the ELB types, and when to use caching with CloudFront, ElastiCache or DAX.

Compute

ServiceWhat it isPriorityMust memorizeKey tip / comparison
Amazon EC2 (families) Virtual machines in the cloud. High General Purpose (T, M): balanced. Compute Optimized (C): CPU-intensive. Memory Optimized (R, X, z): in-memory databases. Storage Optimized (I, D, H): I/O-intensive. Accelerated (P, G, F): GPU/ML. If the question describes the workload — for example "CPU-intensive processing" — the correct family is usually the direct answer.
EC2 Placement Groups Strategies for the physical placement of instances. Medium Cluster: low latency between instances, ideal for HPC. Spread: maximum availability, instances on distinct hardware. Partition: distributed apps like Hadoop or Kafka. "Minimum network latency between instances" → Cluster Placement Group.
AWS Lambda Event-driven serverless compute. High Maximum timeout of 15 minutes. Memory from 128 MB to 10 GB, with CPU scaling proportionally. Cold starts on the first invocation. Default concurrency of 1000, adjustable. Layers for shared code, 5 maximum. "Event-driven, under 15 minutes, no servers to manage" → Lambda is almost always the default serverless answer.
AWS Fargate Serverless compute for containers, used with ECS or EKS. Medium No EC2 instance management. You pay per vCPU and memory used. Each task gets a dedicated kernel, memory and ENI for isolation. Fargate is serverless but more expensive; the EC2 launch type gives full control and savings with Spot.
Amazon ECS AWS-native container orchestrator. Medium Task Definitions are the container blueprint, and Services keep N tasks running, with native integration with ALB, IAM and CloudWatch. Simpler than EKS; ideal when you don't need the standard Kubernetes ecosystem.
Amazon EKS Fully managed Kubernetes. Medium The control plane is managed in a highly-available, multi-AZ setup, and it's compatible with standard (CNCF) Kubernetes. "I need standard Kubernetes or multi-cloud portability" → EKS over ECS.
Amazon ECR Private container image registry. Low Integrated with IAM, encrypted with KMS, with built-in vulnerability scanning. It's the private, secure equivalent of Docker Hub, natively integrated with ECS, EKS and Lambda.
AWS Batch Runs thousands of batch jobs without managing infrastructure. Low Runs on EC2, including Spot, or on Fargate. Manages Job Queues, Job Definitions and Compute Environments. "Massive, fault-tolerant batch processing with dependencies between jobs" → AWS Batch.

High-performance storage

ServiceWhat it isPriorityMust memorizeKey tip / comparison
EBS gp2/gp3 General-purpose SSD. High Between 3000 and 16000 IOPS. Ideal for boot volumes, dev/test and low-to-medium latency apps. The default choice when no extreme IOPS need is specified.
EBS io1/io2 Provisioned IOPS SSD. High Up to 64000 consistent IOPS. Supports Multi-Attach (several instances on the same volume). Ideal for critical transactional databases. "High, consistent IOPS for a critical database" → io1/io2.
EBS st1 / sc1 Throughput-optimized HDD (st1) and cold HDD (sc1). Medium st1 fits big data, data warehousing and streaming, thanks to its sequential throughput. sc1 is for cold data, cheaper, and not bootable. "Low cost, infrequent access, no IOPS requirement" → sc1.
EBS vs Instance Store Comparing block storage options. Medium Instance Store is ephemeral: it's lost when the instance stops or crashes, doesn't support snapshots, but offers higher IOPS. EBS is persistent, supports snapshots, and can be detached/reattached between instances. "Data that must persist after stopping the instance" → EBS, never Instance Store.
EFS: performance and throughput modes EFS performance configurations. Low Performance: General Purpose (low latency) vs Max I/O (high throughput, higher latency). Throughput: Bursting (default), Provisioned and Elastic. Thousands of concurrent connections with more latency tolerance → Max I/O.
Amazon FSx for Windows Managed SMB file system for Windows workloads. Low Native Active Directory integration. Multi-AZ deployment with automatic failover. "Share files with the SMB protocol for Windows apps" → FSx for Windows.
Amazon FSx for Lustre Ultra-high-performance parallel file system, aimed at HPC. Low Sub-millisecond latencies and millions of IOPS. Direct integration with S3, treating objects as files. "HPC, large-scale machine learning, or massive parallel processing" → FSx for Lustre.
FSx for NetApp ONTAP and OpenZFS Managed file systems compatible with NetApp and with ZFS. Low ONTAP supports multiple protocols (NFS, SMB, iSCSI). OpenZFS is aimed at migrating from on-premises ZFS. These rarely show up on the exam; just recognize the name and its general purpose.
S3 Transfer Acceleration Speeds up uploads and downloads using the CloudFront edge network. Medium Useful when users are geographically far from the bucket's region. "Upload large files fast from remote locations" → S3 Transfer Acceleration.

High-performance databases and caching

ServiceWhat it isPriorityMust memorizeKey tip / comparison
Amazon DynamoDB Serverless NoSQL database, with single-digit millisecond latency. High Partition Key or Partition Key plus Sort Key. GSI (an index with a different partition/sort key) vs LSI (same partition key, different sort key, defined when the table is created). On-demand vs provisioned capacity. "Serverless NoSQL with unlimited scaling and millisecond latency" → DynamoDB.
DynamoDB Accelerator (DAX) Managed in-memory cache built specifically for DynamoDB. Medium Cuts latency from milliseconds down to microseconds. It's for DynamoDB only — don't confuse it with ElastiCache. "Minimize DynamoDB read latency as much as possible" → DAX.
Amazon ElastiCache Managed in-memory cache, with Redis or Memcached engines. High Redis offers persistence, multi-AZ replication, complex data structures and pub/sub. Memcached is simple, multi-threaded, with no persistence or replication, only horizontal sharding. User sessions that need high availability → Redis. Simple query caching across multiple cores → Memcached.
Amazon Aurora (performance) See also Domain 2 for its role in resiliency. High Aurora Replicas have under 10 ms lag for read scaling. Parallel Query speeds up analytics on transactional data. Fast, copy-on-write style Cloning is handy for test environments. It beats standard RDS in nearly every performance scenario, except when cost is the top priority.
Amazon Redshift Columnar data warehouse for petabyte-scale OLAP. Medium Uses MPP (Massively Parallel Processing). Redshift Spectrum lets you query S3 without loading the data. Columnar compression reaches around 10x. RDS and Aurora are for transactional OLTP. Redshift is for analytical OLAP, with complex queries over huge volumes.

Streaming and real-time ingestion

ServiceWhat it isPriorityMust memorizeKey tip / comparison
Kinesis Data Streams Real-time data streaming with full control. Medium Manually scalable shards. Configurable retention from 1 to 365 days. Custom consumers via KCL. If you need custom processing and the ability to replay events → Data Streams.
Kinesis Data Firehose Automatic streaming delivery to S3, Redshift, OpenSearch or Splunk. Medium Fully managed, near-real-time, with a buffer of roughly 60 seconds. Requires no shard management. If you only need to ingest and deliver without custom processing → Firehose (simpler than Data Streams).
Kinesis Video Streams Ingests and stores video streams for ML-based analysis. Low Integrates with Rekognition Video. Any scenario that mentions "video streaming for analysis" → Kinesis Video Streams.
Amazon MSK Fully managed Apache Kafka. Low Use it when a Kafka ecosystem already exists, thanks to its native API compatibility — not as a generic Kinesis replacement. "Migrate an existing on-premises Kafka to AWS" → MSK. For a brand-new app with no Kafka tie-in, Kinesis is usually simpler.

High-performance networking

ServiceWhat it isPriorityMust memorizeKey tip / comparison
Application Load Balancer (ALB) Layer 7 ELB, for HTTP/HTTPS. High Routes by path, host, headers or query string. Targets can be EC2, IP or Lambda. Supports WebSocket. Any HTTP/HTTPS web scenario with advanced routing → ALB.
Network Load Balancer (NLB) Layer 4 ELB, for TCP/UDP, ultra performance. High Handles millions of requests per second. Provides a static IP per AZ and preserves the client's source IP. "I need a static IP" or "extreme-throughput gaming/IoT" → NLB.
Gateway Load Balancer (GWLB) Layer 3 ELB, for third-party appliances. Low Designed to transparently insert third-party firewalls, IDS or IPS into the traffic flow. "Insert a partner's security appliance into the traffic path" → GWLB.
Amazon CloudFront Global CDN with 450+ edge locations. High Caches both static and dynamic content. Signed URLs and Signed Cookies for private content. Lambda@Edge for edge logic. Origin failover for high availability. Reduces global latency and offloads the origin. See the comparison with Global Accelerator below.
AWS Global Accelerator Two static Anycast IPs that route over AWS's private network. Medium Doesn't cache: it's a smart proxy, not a CDN. Failover happens in under 30 seconds. Useful for non-HTTP apps, like TCP or UDP. "I need global static IPs" or "improve performance for non-HTTP protocols" → Global Accelerator.
Amazon API Gateway Creates, publishes and manages REST, HTTP and WebSocket APIs. High REST API: full-featured, with caching and transformation. HTTP API: simpler, cheaper and lower latency. WebSocket API: bidirectional communication. It's the standard front door for serverless architectures with Lambda behind it.
AWS Direct Connect Dedicated network connection between on-premises and AWS. Medium Offers 1, 10 or 100 Gbps. Not encrypted by default; VPN over DX can be layered on if required. Setup takes weeks. "Consistent, high-bandwidth connection" → Direct Connect. If a fast setup is needed → Site-to-Site VPN.
AWS Transit Gateway Central hub for interconnecting VPCs and on-premises networks. Medium Uses a hub-and-spoke architecture, simplifying the complex mesh topology of VPC Peering. Supports multicast. "Connect dozens or hundreds of VPCs without a peering mesh" → Transit Gateway.
AWS PrivateLink Private connectivity between VPCs and AWS services, without traversing the public internet. Medium Interface Endpoints: an ENI with a private IP, for most services. Gateway Endpoints: only for S3 and DynamoDB, via a route table, with no hourly cost. "Access S3/DynamoDB from a private subnet without going out to the internet or using NAT" → Gateway Endpoint (cheaper than an Interface Endpoint).
Amazon VPC (components) Isolated virtual network. High A public subnet has a route to an Internet Gateway; a private subnet uses a NAT Gateway for outbound traffic. The NAT Gateway is managed and scalable; the NAT Instance is manual and now considered legacy. It's the foundation of nearly every architecture diagram on the exam; review it until it's automatic.
Route 53 (latency and geo routing) See also Domain 2 for failover. High Latency-based: routes to the lowest-latency endpoint. Geolocation: by user location, useful for regulatory compliance. Geoproximity: by proximity with an adjustable bias. Weighted: percentage-based distribution, ideal for blue/green. Memorize which policy maps to each keyword in the question (see the Trigger Words section).

4. Designing Cost-Optimized Architectures 20% of the exam
This is the most "mathematical" domain: it's about recognizing the correct pricing model for the usage pattern, whether predictable, interruptible or variable. Memorize the S3 classes and EC2 purchasing models well.

Compute pricing models

ServiceWhat it isPriorityMust memorizeKey tip / comparison
EC2 On-Demand Pay per second, no commitment. High Offers maximum flexibility, at the highest hourly cost. Ideal for new or short-term unpredictable workloads. It's the baseline for comparing every other model.
EC2 Reserved Instances (RI) 1- or 3-year commitment, with up to 75% discount. High Standard RIs are locked to an instance family and region; Convertible RIs offer some flexibility. "Predictable, stable long-term workload" → RI or Savings Plans, depending on how much flexibility is needed.
EC2 Spot Instances Up to 90% discount, interruptible with 2 minutes' notice. High Ideal for fault-tolerant workloads: batch, rendering, big data, CI/CD. "Lowest possible cost" combined with "tolerates interruptions" → Spot is almost always the answer.
Dedicated Hosts and Dedicated Instances Dedicated or isolated physical hardware. Low The most expensive option. Used for licensing requirements (BYOL) or strict compliance, not for cost optimization. If the question mentions "existing licenses tied to socket or core" → Dedicated Host.
Savings Plans (Compute vs EC2 Instance) Usage-commitment discount, 1 to 3 years, measured in dollars per hour. High Compute Savings Plans: up to 66% discount, applies to EC2, Fargate and Lambda in any region, family or OS (maximum flexibility). EC2 Instance Savings Plans: up to 72%, but locked to a specific instance family and region. "Stable commitment but I need flexibility across EC2, Fargate and Lambda" → Compute Savings Plans.

Cost-optimized storage

ServiceWhat it isPriorityMust memorizeKey tip / comparison
S3 Standard Frequent access, for general-purpose use. High Offers 99.99% availability, with no minimum storage duration. It's the starting point; you optimize by moving data to other classes based on age or access frequency.
S3 Standard-IA and One Zone-IA Classes for infrequent access. High Require a 30-day minimum storage duration. One Zone-IA lives in a single AZ, is cheaper but less durable if that AZ is lost, and only suits recreatable data. "Data accessed a few times a month but critical" → Standard-IA. "Non-critical, recreatable data" → One Zone-IA.
S3 Intelligent-Tiering Automatically moves data between tiers based on its access pattern. Medium Ideal when you don't know the data's access pattern. "I don't know how the data will be accessed going forward" → Intelligent-Tiering.
S3 Glacier Instant and Flexible Retrieval Classes for long-term archiving. High Instant Retrieval responds in milliseconds. Flexible Retrieval responds in minutes or hours: Expedited in 1 to 5 minutes, Standard in 3 to 5 hours, and Bulk in 5 to 12 hours. "Archive rarely queried but sometimes needed quickly" → Glacier Instant Retrieval.
S3 Glacier Deep Archive The cheapest storage class of all. High Retrieval takes hours, sometimes more than 12. Requires a 180-day minimum storage duration. Built for multi-year compliance. "Regulatory retention of 7+ years, with almost no access" → Glacier Deep Archive.
S3 Lifecycle Policies Automates the transition between storage classes. High A typical example: Standard for days 0–30, Standard-IA for days 30–90, Glacier from day 90, and Deep Archive from day 180. Configured at the bucket or prefix level. Any question about automatically optimizing long-term storage cost → Lifecycle Policy.

Databases and cost monitoring

ServiceWhat it isPriorityMust memorizeKey tip / comparison
Aurora Serverless Aurora with capacity auto-scaling and automatic pausing. Medium You pay per ACU (Aurora Capacity Unit) per second. Version 2 scales in fractions of a second. "Intermittent or unpredictable database workload, sometimes with no traffic at all" → Aurora Serverless.
DynamoDB On-Demand vs Provisioned DynamoDB capacity modes. Medium On-Demand charges for actual usage and is ideal for unpredictable traffic. Provisioned is cheaper when traffic is predictable and steady. "I don't know how much traffic I'll get" → On-Demand.
AWS Cost Explorer Visual tool for analyzing cost and usage. Medium Shows up to 12 months of history and a 12-month forecast, plus RI and Savings Plans recommendations. "Visualize cost trends and forecast future spend" → Cost Explorer.
AWS Budgets Custom budgets with alerts. High Sends alerts via email or SNS when thresholds are exceeded, and can trigger automatic actions such as stopping resources or applying SCPs. "Get an automatic alert if spend exceeds a certain amount" → AWS Budgets.
Cost and Usage Report (CUR) Detailed, granular cost-and-usage report. Low Delivered to S3 and analyzed with Athena or QuickSight. The most detailed of all billing reports. "Deep financial analysis or internal chargebacks" → CUR.
AWS Trusted Advisor Automatic recommendations covering cost, security, performance, fault tolerance and service limits. Medium The Basic tier includes 7 checks; Business/Enterprise include all checks. Detects idle or unused resources. "Find unused resources to cut cost" → Trusted Advisor, in its Cost Optimization category.

5. Management, Monitoring and Governance
These services cut across all 4 domains: they show up in security questions (auditing), resiliency questions (monitoring) and cost questions (compliance). All of them have a medium-to-high chance of appearing.
ServiceWhat it isPriorityMust memorizeKey tip / comparison
Amazon CloudWatch Monitoring for metrics, logs and alarms. High Metrics arrive every 5 minutes for free, or every 1 minute in custom/detailed mode. 12. Critical comparisons (memorize, no excuses)
These are the comparisons that come up most often in real exam questions, based on patterns from your guides. Know this section cold and you'll clear a large share of the "trap" questions.
ComparisonKey difference
RDS Multi-AZ vs Read ReplicasMulti-AZ is high availability: synchronous, automatic failover, same endpoint. Read Replicas are read performance: asynchronous, manual promotion, a different endpoint.
RDS, DynamoDB, Redshift and AuroraRDS and Aurora are relational OLTP. DynamoDB is serverless NoSQL key-value. Redshift is OLAP, a petabyte-scale data warehouse.
S3, EBS, EFS and FSxS3 is object storage, unlimited and global. EBS is block storage, in a single AZ, tied to one instance. EFS is shared, multi-AZ NFS file storage, Linux only. FSx are specialized managed file systems, such as Windows or Lustre.
ALB, NLB and GWLBALB is Layer 7, HTTP/HTTPS, with advanced routing. NLB is Layer 4, TCP/UDP, with a static IP and maximum throughput. GWLB is Layer 3, for third-party appliances.
CloudFront vs Global AcceleratorCloudFront caches content, acting as a CDN. Global Accelerator doesn't cache: it's a network proxy that improves routing and provides static IPs, useful for non-HTTP traffic.
Direct Connect vs Site-to-Site VPNDirect Connect is a dedicated connection, with higher bandwidth, no native encryption, and weeks of setup. VPN runs over the public internet, with automatic IPsec encryption and minutes of setup.
Security Groups vs NACLsSG is stateful, at the instance level, allow rules only. NACL is stateless, at the subnet level, with both allow and deny rules.
KMS, CloudHSM and Secrets ManagerKMS is multi-tenant managed encryption for general use. CloudHSM is dedicated hardware, FIPS 140-2 level 3. Secrets Manager manages credentials with automatic rotation.
Cognito User Pools vs Identity PoolsUser Pools handle authentication, a user directory. Identity Pools handle authorization, with temporary AWS credentials.
SNS, SQS and EventBridgeSNS is pub/sub with immediate fan-out. SQS is a message queue for decoupling and buffering. EventBridge is complex event routing with multiple rules and sources.
Kinesis Data Streams vs FirehoseData Streams gives full control, with manual shards and event replay. Firehose delivers automatically and simply to a destination, with no shard management.
EC2, Lambda and FargateEC2 gives full control, for long-running workloads. Lambda is serverless, event-driven, with a 15-minute cap. Fargate is serverless containers, no EC2 management.
On-Demand, Reserved, Spot and Savings PlansOn-Demand is flexible but expensive. RI and Savings Plans pay off for predictable workloads. Spot is interruptible and delivers maximum savings for fault-tolerant workloads.
Route 53: Failover, Weighted, Latency and GeolocationFailover is active-passive with a health check. Weighted distributes by percentage, ideal for blue/green. Latency targets the lowest possible latency. Geolocation routes based on the user's location, for regulatory compliance.
